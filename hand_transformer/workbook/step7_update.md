# ステップ7 更新して、もう一度予測する（7.1–7.4）

**目標**：ステップ6 の勾配で180個のパラメータを1回だけ更新し、もう一度順伝播して、損失が下がり予測が正解にひっくり返るのを確かめます。再順伝播の**前に**、下がり幅を勾配だけから予言しておきます。

- **目安時間**：4.75 時間（7.1–7.2 更新と1次予測 1.0h ＋ 7.3–7.4 2回目の順伝播と比較 3.75h）
- **対応チェックポイント**：7.1–7.4

> **2回目の順伝播は隠れた山場です。** 1回目は U1 が ±1、重みが 0.5 刻みだったので、掛け算のほとんどは「符号付きコピー」か「半分にする」でした。
> 更新後はどちらも4桁の小数になり、掛け算の大半が小数×小数になります（手順 7.3）。
> 時間が足りなければ、「遅れたときのショートカット」の B〜D を使ってください。

## 手順

始める前に、下の「計算する前に予想しよう」の3問に、自分の予想を書いておいてください。

### 7.1 更新（lr = 1 なので引き算だけ）

1. **θ' = θ − lr·dθ = θ − dθ** を180個すべてに行います。勾配の**逆**向きに動かすので、符号に注意してください。
2. **計算しなくてよいもの**：勾配が厳密に0の**20個**は変わりません（E の 鳴く・。 行 8個、Wk の d0 行 4個、W1 の h3 列 4個、W2 の h3 行 4個）。さらに**6個**は変化が 0.00005 未満で、4桁では変わりません（Wq の d1 列 4個、Wk の (d3, d0) と (d3, d1)）。
3. **X0' は近道で**：E と P は同じ勾配を受け取る（dE の使われた行 = dP）ので

   $$X_0' = E'[\mathrm{ids}] + P' = X_0 - 2\,\mathrm{lr}\; dX_0$$

   この式で X0' を直接求め、E'[ids] + P' と一致するかで検算します。

### 7.2 1次予測（再順伝播の前に！）

derivations.md 問9 のとおり、$L(\theta - \eta g) \approx L(\theta) - \eta\,\lVert g\rVert^2$ です。

1. パラメータ群ごとに勾配の二乗和を求めます（電卓で x² → M+）。0のマスは飛ばします。‖dE‖² = ‖dP‖²（同じ数が並ぶ）なので、1回求めて2倍します。
2. 9群を足して ‖g‖² とし、**予測 ΔL = −lr·‖g‖²** を 7.2 の表に記入します。
3. 予測される L' = L + 予測 ΔL も計算しておきます（→ 予想1）。

### 7.3 2回目の順伝播

ステップ2〜5 の手順（2.1 → 5.3）を、θ' でもう一度行います。

**本当のコスト**（掛け算の数。数え方は [cost.md](cost.md) と同じで、LN の二乗を含み、Q の t0 行など構造的に省ける分は除く。記録した4桁の値で分類し、コードで数えた値）

| | 1回目 | 2回目 |
|---|---:|---:|
| 掛け算の総数 | 484 | 484 |
| 0 との積（飛ばせる） | 202 | 56 |
| 片方が ±1（符号付きコピー） | 182 | 28 |
| 片方か両方が 0.5 刻み（暗算・半分） | 92 | 0 |
| **小数×小数** | **8** | **400** |

2回目は、掛け算の8割以上が4桁×4桁になります（丸めずに判定すると 412 回）。

1回目の工夫のうち、**まだ使えるもの**：

- A' の t0 行は [1, 0, 0] のまま → **Q' の t0 行は不要**、O'[t0] = V'[t0]
- ReLU の発火パターンは1回目と同じ10マス → h3 はまだ死んでいます（Z' の h3 列 = −0.6138, −0.7650, −1.4857）。R' が0のマスに掛かる W2' の行は飛ばせます
- Wk' の d0 行は (0, 0, 0, −1) のまま（dWk の d0 行が0だったから）

**もう使えないもの**：U1' はもう ±1 ではありません（t0 行 = 0.8903, 0.9184, −1.5078, −0.3009。σ も 0.5 → 0.4784）。重みもすべて4桁の小数です。

[answers.md の 7.3](answers.md#73-再順伝播主要な中間値) には、1回目と同じ順序で σ'・Q'・K'・V'・S'・A'・Attn'・U2'・Z'・F'・logits' など途中の値もすべて載っています。行ごとに照合しながら進めてください（ショートカット B もここから写します）。

### 7.4 比較

1. **L'** を求めます：3位置の平均の (logsumexp − 正解の logit')。−log p' ではなくこの形で計算します。
2. **実際の ΔL = L' − L** を 7.2 の予測と並べ、比（実際 / 予測）を出します。
3. 正解トークンの確率の表を埋め、各位置の argmax（予測トークン）が変わったかを確かめます。
4. ヘッド0 の t2（が）の行 A0'[t2] を、3.3 の A0[t2] と比べます。
5. （任意・予備時間で）**数値微分で勾配を1つ確かめる**：Wout[d0, 鳴く] を ±h だけ動かして L を測り、$\big(L(+h) - L(-h)\big)/(2h)$ を 6.1 の dWout[d0, 鳴く] = −0.3373 と比べます。
   動くのは logits の「鳴く」列だけで、もとは全部0なので、新しい値は ±h·X2[t, d0] そのものです。各行で exp 1回と log 1回を計算し直せば足ります（h = 0.1 では行の最大値が変わらないので、5.2 で求めた他の4列の exp をそのまま使えます）。発展課題 [extras/numgrad_by_hand.py](../extras/numgrad_by_hand.py) と同じ成分です。

<details><summary>数値微分の値（h = 0.1、コードで計算）</summary>

| | logits の 鳴く 列（t0, t1, t2） | nll t0 | nll t1 | nll t2 | L |
|---|---|---:|---:|---:|---:|
| 元 | 0, 0, 0 | 1.464085 | 1.319002 | 1.401493 | 1.394860 |
| +h | −0.0736, 0.0714, 0.1296 | 1.452664 | 1.327552 | 1.305377 | 1.361864 |
| −h | 0.0736, −0.0714, −0.1296 | 1.476234 | 1.310974 | 1.500728 | 1.429312 |

(1.361864 − 1.429312) / 0.2 = −0.3372。解析的な勾配は −0.3373 で、差は中心差分の誤差（h² に比例）です。
（表はコードの全桁から計算しています。5.1 の4桁の logits から計算すると小数5桁目が数単位ずれます。例：+h の t0 は 1.452625。差分 −0.3372 は同じです）
L を小数4桁で持つと (1.3619 − 1.4293) / 0.2 = −0.3370 になります。h を小さくしすぎると引き算で桁が消えるので、手計算では h = 0.1 程度が適当です。
t2 の nll が一番大きく動くのは、t2 の正解が「鳴く」で、X2[t2, d0] = 1.2963 が3位置で一番大きいからです。
</details>

## 計算する前に予想しよう

**予想1　1次予測は当たるか**：7.2 の予測 ΔL を L = 1.3949 に足すと、予測 L' はいくつ？ それはありうる値？ 実際の L' は予測より上？下？

<details><summary>答え</summary>

1.3949 − 1.4701 = −0.0752。交差エントロピーは必ず0以上なので、**ありえない値**です。
1次近似は「今の傾きのまま、まっすぐ下る」と仮定していますが、実際の損失の曲面は曲がっています（2次以上の項）。
実際は L' = 0.1056（ΔL = −1.2893、予測の 0.877 倍）。
同じ勾配で lr だけ変えると、実際 / 予測の比は lr = 0.1, 0.25, 0.5 で 1.027, 1.059, 1.080（実際のほうが少し大きく下がる）、lr = 1 で 0.877、lr = 2 で 0.473 です（コードで計算）。つまり lr = 1 では、**実際の L' は予測より上**です。損失は0より下がれないので、lr が大きいほど実際の下がり幅は予測の下がり幅より小さくなります（実際 / 予測 < 1）。
</details>

**予想2　注意はどこへ動くか**：ヘッド0 で、t2（が）のクエリは今 `<s>` に 0.7425、猫 に 0.2571 を払っています（3.3）。更新後はどうなるでしょう？

<details><summary>答え</summary>

猫 へ移ります：A0'[t2] = (0.2194, 0.7795, 0.0011)。更新前の点では、V0 の k1 行 (1, 2) を多く混ぜるほど t2 の損失が下がる向きだったからです（dA0[t2] = (0, −0.0664, −0.0192)）。ただし「主語を見て『鳴く』を当てる」ようになったわけではありません。この1文では直前の「が」だけで答えが決まり、更新後のヘッド0 はむしろ t2 の「鳴く」の logit を 0.6423 下げています（`python3 extras/decompose_update.py`）。注意が動くこと＝意味のある働き、とは限りません。意味のある注意の使い方は発展課題 M1（2文タスク）で見られます。
</details>

**予想3　Wout だけ更新したら**：Wout だけを更新すると（ショートカット D）、L はどこまで下がり、予測はいくつ正解になるでしょう？ 全部を更新したときの下がり幅の何割でしょう？

<details><summary>答え</summary>

L = 0.7473（ΔL = −0.6475）で、予測は3つとも正解になります。全体の下がり幅 −1.2893 の約50%（50.2%）で、‖g‖² に占める Wout の割合 51.8% とほぼ同じです。残りの半分は、他の8群が協力して稼いでいます（「見どころ」4）。
</details>

## よくあるミス

- **符号を逆にする**：θ + dθ にすると損失は上がります。
- **E と P の片方しか更新しない**：X0' = X0 − dX0 になってしまいます。正しくは X0 − 2·dX0 です。
- **2回目の順伝播に古い値が混ざる**：特に、U1 = ±1 のつもりで符号コピーしてしまう、古い Wout を使う。
- **1回目の近道を無条件に使う**：Q' の t0 行と h3 はまだ省けますが、U1' の符号コピーや「重みが0.5刻み」はもう使えません。
- **‖g‖² の数え方**：E と P は別々のパラメータなので両方数えます。二乗せずに足したり、√ を取ったりしないこと。
- **ショートカット D で X2'（更新後）を使う**：D は「Wout だけを更新した」別の実験なので、X2 は 4.5 の更新前の値を使います。
- **更新後の重みを2桁に丸める**：変化量の多くは 0.01〜0.1 程度なので、4桁は必要です。
