<details><summary>採点の目安 (c) 1次予測</summary>

- 予測 ΔL = −lr‖g‖² = −1.4701（‖g‖² = 1.4701、うち Wout が 51.8%）。実際は L = 1.3949 → 0.1056 で ΔL = −1.2893。比は 0.877

- **lr を小さくすると**：比は lr = 0.01 で 1.003、0.1 で 1.027、0.5 で 1.080 と、**1を超えます**（`python3 extras/lr_scan.py`）。勾配方向に沿った損失 L(θ − ηg) の曲率が η = 0 では負（−0.8270）で、はじめは直線より速く下がるからです。曲率は η = 0.3 と 0.35 の間で正に変わり、lr = 1 では「平らになる」効果が勝ちます。lr → 0 で比は1に近づきます
- 2次の項まで入れた予測（−1.4701 − 0.8270/2 = −1.8836）は、かえって外れます。1次予測は「今の傾き」だけを使う、η が小さいときの近似です

</details>

### 8-3 理解チェック（30分、10問）

各問、紙に3〜5文で答えてから開きます。

**問1　÷3 を忘れたら、L' が下がった**：dlogits の ÷3 を忘れて逆伝播と更新をすると、L' = 0.0002 で、正しい勾配の 0.1056 より**低く**なります（`python3 extras/bug_signatures.py`）。なぜですか？ ここから何が言えますか？ どの検算ならこのミスを見つけられますか？

<details><summary>答えの要点</summary>

- 逆伝播はすべて線形なので、dlogits が3倍になると180個の勾配が**ちょうど3倍**になります。向きは正しいまま、lr = 3 で進んだのと同じです。
- この勾配方向に沿った損失は η = 2 で 0.0030、η = 4 で 2.2×10⁻⁵、η = 6 で 3.2×10⁻⁶ と下がり続ける（`python3 extras/lr_scan.py` の [3]）ので、3倍の歩幅のほうが低くなります。
- 同じことは他のバグでも起きます。dV = A dO と転置を忘れると L' = 0.1034、dQ・dK の 1/√2 を忘れると 0.0946 で、どちらも正しい 0.1056 より低い（`bug_signatures.py`）。**損失が下がること、正しい答えより下がることさえ、勾配が正しい証明にはなりません。**
- dlogits の行和0、LN経由の和0・直交などの検算は、全体を3倍しても成り立つので見つけられません。見つけられるのは、answers.md との照合（6.1 で最初にずれる）と、数値微分（`python3 mini_gpt.py --gradcheck`、発展課題 M2）です。

</details>

**問2　dWk の d0 行と dQ の t0 行**：どちらも厳密に0でした。理由は同じですか？ 更新後の θ' でもう一度勾配を求めると、それぞれどうなりますか？

<details><summary>答えの要点</summary>

- **dQ の t0 行**：t0 は因果マスクで自分しか見られず、要素1つの softmax は定数1。t0 のクエリをどう動かしても A は変わりません。**どんな重み・入力でも0**（構造）。2ステップ目も0です。
- **dWk の d0 行**：dWk[d0] = Σ_t U1[t, d0]·dK[t] で、U1 の d0 列が**たまたま**3位置とも +1 なので、これは dK の列和です。dS の行和が0なので dK の列和は0（全キーに同じベクトルを足しても softmax は変わらない）。**この入力だから0**です。
- 更新後は U1' の d0 列が (0.8903, 1.0270, 0.9598) とそろわなくなり、2ステップ目の dWk の d0 行は (−0.0002, 0.0020, −0.0020, 0.0027) と0でなくなります（コードで計算）。

</details>

**問3　「0」と「0.0000」**：dQ0 の (t1, d1) は厳密に0（「0」）なのに、dWq の d1 列は (−1.33, +1.33, +1.33, −1.33)×10⁻⁶（「0.0000」）です。何が違いますか？

<details><summary>答えの要点</summary>

- dS の行和は0なので、クエリの勾配 $dq_i = \frac{1}{\sqrt2}\sum_j dS_{ij}\,k_j$ は、見たキーどうしの**差**にしか反応しません。
- t1 が見る k0, k1 は、ヘッド0 の d1 成分がともに −1 なので、dQ0 (t1, d1) は厳密に0です。
- t2 は k2 も見ていて、k2 の d1 成分（+1）だけが違うので、dQ0 (t2, d1) は0になりません。ただし A0 (t2, k2) = 4.43×10⁻⁴ と飽和しているので dS0 (t2, k2) = −9.4×10⁻⁷ しかなく、dQ0 (t2, d1) = √2·dS0 (t2, k2) ≈ −1.33×10⁻⁶。dWq の d1 列はこれを U1 の t2 行の符号で並べたものです。
- 「飽和した softmax は勾配をほとんど通さない」が、厳密に止めるのは要素1つ（t0）の場合だけです。

</details>

**問4　行和がそろう**：dX2・dX1・dX0 の各行の和は、3つとも (0.0602, 0.1599, −0.0123) です。なぜですか？ この検算で見つかるミスと、見つからないミスを1つずつ挙げてください。

<details><summary>答えの要点</summary>

- LN の逆伝播の出力（LN2経由・LN1経由）は、各行の和が0です（全成分に同じ数を足しても LN の出力は変わらないから）。dX1 = dX2 + LN2経由、dX0 = dX1 + LN1経由なので、行和は変わりません。
- **見つかる**：残差での足し忘れ。dX1 = LN2経由だけにすると dX1 の行和が0になります（`bug_signatures.py` では 6.3 で最初にずれ、L' = 0.6496）。LN の逆の途中の計算ミスも、多くは行和0が崩れて見つかります。
- **見つからない**：÷3 忘れ（3つとも3倍になってそろったまま）、LN の逆で σ と σ² を取り違える（LN経由の大きさだけが変わり、行和は0のまま）。

</details>

**問5　死んだユニット**：h3 の dR の列は (−0.0465, 0.0514, 0.0276) と0ではなく、W2 の h3 行も [0, 0, 1, 1] と0ではないのに、dW1 の h3 列と dW2 の h3 行は厳密に0でした。なぜですか？ h3 はずっと死んだままですか？

<details><summary>答えの要点</summary>

- dW2[h3] = Σ_t R[t, h3]·dF[t] で、R の h3 列が全部0。dZ の h3 列も ReLU の門で0になるので、dW1[:, h3] = U2ᵀ dZ[:, h3] = 0。dR が0でなくても、門の手前で止まります。
- W1 の h3 列は更新されませんが、Z[:, h3] = U2·W1[:, h3] は **U2 が動けば動きます**。1ステップ後の Z' の h3 列は (−0.6138, −0.7650, −1.4857) で、t0 と t2 が0に近づきました。同じ SGD（lr = 1）を続けると、9回更新したあとに t0 で Z = 0.0004 > 0 となり、h3 は発火します（`mini_gpt.py` の forward・backward・sgd で確認）。
- 自分の重みに勾配が来なくても、ほかの層が変われば生き返ることがあります。

</details>

**問6　0 の重みと勾配**：Wout の「鳴く」列は全部0でした。dX2 = dlogits Woutᵀ には dlogits の「鳴く」列が効かないのに、dWout の「鳴く」列は (−0.3373, −0.1518, −0.0373, −0.2920) と0ではありません。なぜですか？

<details><summary>答えの要点</summary>

- dX = dY Wᵀ は重みを逆向きにたどるので、0 の重みは**入力側への勾配**を止めます。
- dW = Xᵀ dY は「入力 × 出力側の勾配」で、重み自身の値によりません。0 の重みも、入力 X2 と dlogits が0でなければ学習されます。更新後の「鳴く」列は (0.3373, 0.1518, 0.0373, 0.2920) です。
- 1列を0にした初期値で一般性を失わないのは、Wout のすべての列から同じ列ベクトルを引いても、各行の logits から同じ数が引かれるだけで p が変わらないからです（README §8 の 5.2）。

</details>

**問7　E と P の近道**：7.1 で X0' = X0 − 2·lr·dX0 と近道できたのはなぜですか？ この近道が成り立たないのは、どんな場合ですか？

<details><summary>答えの要点</summary>

- 各トークンが1回ずつ、別々の位置に出てくるので、dE の使われた行 = dP の同じ位置の行（= dX0 の行）。X0' = (E − lr·dE)[ids] + (P − lr·dP) = X0 − 2·lr·dX0 です。
- 成り立たないのは、同じトークンが2回出る場合（dE の行が2つの dX0 の行の和になる）や、P を複数の文で共有する場合です。Part 2 では P を猫文と犬文で共有し、`<s>` と「が」が両方の文に出るので、6行すべてで X0' ≠ X0 − 2·lr·dX0 です（`part2/mini_gpt2.py` で確認）。

</details>

**問8　LN1 経由の形**：LN1経由の t0 行は (−0.0528, 0.0528, 0.1044, −0.1044) と「±a, ±b」の形でした。なぜこの形になりますか？ σ1 = 0.5 の t0 行は勾配が2倍になる、とはどういう意味ですか？

<details><summary>答えの要点</summary>

- LN の逆 (dU − m₁ − U·m₂)/σ は、dU から「全成分が同じ方向」と「U の方向」を取り除いて σ で割る操作です。結果は各行の和が0、U と直交します（LN が全体のずらしと拡大縮小を無視することの裏返し）。
- U1 の t0 行は (+1, +1, −1, −1) なので、和0と直交の2つから、+1 の2成分の和も −1 の2成分の和も0 → (d0, d1) と (d2, d3) がそれぞれ (a, −a)、(b, −b) になります（ステップ6 の「ペアの規則」）。d = 3 の Part 1.5 では、残る向きが1本だけになります。
- σ が小さい行は、入力を少し動かしただけで U が大きく変わるので、勾配が 1/σ 倍に大きくなります。t0（σ = 0.5）は2倍、t1（σ = 2）は半分です。

</details>

**問9　因果マスクを外すと**：マスクを外すと（t0 も k1, k2 を見られる）、6.5–6.6 の厳密な0のうち、どれが0でなくなりますか？ どれは0のままですか？ そのとき学習の何が問題ですか？

<details><summary>答えの要点</summary>

- **0でなくなる**：dS0・dS1 の t0 行と dQ の t0 行。t0 の softmax が3要素になるので、t0 のクエリにも勾配が来ます（dQ の t0 行 = (−0.0424, −0.0617, −0.1517, −0.0091)、コードで計算）。順伝播でも Q の t0 行が必要になります。dQ0 の (t1, d1) と dQ1 の (t1, d3) も0でなくなります（−0.0016、0.0071）。t1 も k2 を見るようになり、k2 だけ d1・d3 成分が +1 で、k0・k1 の −1 と違うからです。
- **0のまま**：dA0 の k0 列（V0 の t0 行が (0, 0) なのはマスクと関係ない）、dWk の d0 行（U1 の d0 列が +1 でそろっている）、dE の 鳴く・。 行。
- 問題：t0 が t1 の入力（= t0 の正解「猫」）を見られるので、学習データの上ではカンニングで損失が下がるのに、`<s>` から1語ずつ生成すると壊れます（発展課題 S1、`python3 extras/no_mask.py`）。

</details>

**問10　注意は動いたが**：更新で、ヘッド0 の t2（が）の注意は `<s>` 0.7425 → 0.2194、猫 0.2571 → 0.7795 へ移りました。「t2 は主語の猫を見て『鳴く』を当てるようになった」と言えますか？

<details><summary>答えの要点</summary>

- 言えません。更新後のヘッド0 は、t2 の「鳴く」の logit をむしろ 0.6423 **下げて**います（`python3 extras/decompose_update.py`。最終 LN が無いので logits は直接経路・ヘッド0・ヘッド1・FFN の和に厳密に分かれる）。t2 の「鳴く」を押し上げたのは主に FFN（+2.5449）です。
- 注意が猫へ動いたのは、更新前の点で V0 の k1 行を多く混ぜるほど t2 の損失が下がる向きだった（dA0[t2] = (0, −0.0664, −0.0192)）からで、「主語を見る」役割を覚えたからではありません。
- このタスクは直前の1語で答えが決まるので、Attention が無くても解けます。Attention でしか解けない場面は Part 2（猫文と犬文）で、t2 の入力がどちらも「が」なので、t1 を振り返らないと 鳴く か 吠える かを決められません。

</details>
