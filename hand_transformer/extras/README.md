## must

### M1 2文タスク：Attention が本当に必要な場面

**何をするか**：`<s> 猫 が → 猫 が 鳴く` と `<s> 犬 が → 犬 が 吠える` の2文を同時に学習させ、Attention あり / なしで比べます（語彙7、Adam 3000ステップ）。

**なぜ理解が深まるか**：本編のタスクは「直前の1語だけで次が決まる」ので、実は Attention が無くても解けます（README の「このタスクの正直な限界」）。
2文タスクでは位置2の入力がどちらも「が」なので、**位置1を振り返らないと「鳴く」か「吠える」か決められません**。
Attention の役割が「他の位置から情報を運ぶこと」だと、損失の数字ではっきり分かります。

**手 / コード・時間**：コード、30分（実行前に「どのヘッドがどこを見るようになるか」を予想しておく）

**実行**：`python3 extras/two_sentences.py`

<details><summary>実際の結果</summary>

損失の下限は、位置0（`<s>` の次が 猫 か 犬 か）がどちらのモデルでも原理的に当てられないことから決まります。

| | 理論下限 | 学習後の損失 | 位置2（が）の次の確率 |
|---|---:|---:|---|
| Attention あり | 2·ln2/6 = 0.2310 | **0.2311** | 文0：P(鳴く) = 1.000、文1：P(吠える) = 1.000 |
| Attention なし | 4·ln2/6 = 0.4621 | **0.4621** | 両方の文で P(鳴く) = 0.498、P(吠える) = 0.502（五分五分に張り付く） |

位置2（が）のクエリが払う注意（列 = `<s>`, 猫/犬, が）：

| | 文0（猫） | 文1（犬） |
|---|---|---|
| ヘッド0 | [0.016, 0.149, **0.835**] | [0.001, **0.944**, 0.055] |
| ヘッド1 | [0.593, 0.097, 0.310] | [0.598, 0.090, 0.312] |

**ヘッド0 は「犬検出器」**になりました。犬の文では位置1（犬）を 0.944 で見て、猫の文では自分自身（が）を見ます。
ヘッド1 は2文でほぼ同じ重みなので、2文を区別する情報は運んでいません。

**正直な注意**：seed を変えると、うまくいかないこともあります。`no_mask.py`（S1）で seed 0〜9 を試すと、マスクありのモデルは
9/10 が下限 0.2311 に到達しましたが、seed 8 は **0.4621（Attention なしと同じ下限）で止まりました**。
Attention を使う解は、勾配降下で必ず見つかるとは限りません。
</details>

### M2 Wout の1成分を手で数値微分する

**何をするか**：Wout[d0, 鳴く] を ±h だけ動かしたときの損失 L(+h), L(−h) を手で計算し、中心差分 (L(+h) − L(−h))/2h を 6.1 の dWout[d0, 鳴く] = −0.3373 と比べます。
README §6 の予備時間「余れば手で数値微分」の課題です（本編の手順書 [`workbook/step7_update.md`](../workbook/step7_update.md) と合わせて使ってください）。

**なぜ理解が深まるか**：逆伝播で求めた数が「パラメータを少し動かしたときの損失の変化率」そのものだと、自分の手で確かめられます。
また h の選び方（大きすぎると近似が粗く、小さすぎると4桁の手計算では引き算で桁が消える）を体感できます。

**手 / コード・時間**：手、30分。答え合わせに `python3 extras/numgrad_by_hand.py`

**手順**：

1. Wout[i, j] を h 動かすと、変わるのは logits の j 列だけで、変化量は h·X2[:, i] です。**順伝播をやり直す必要はありません**。
2. 4.5 の X2 の d0 列と、5.1 の logits を用意します。「鳴く」列はもともと全部 0 なので、書き換え後の値は h·X2[t, d0] そのものです。
3. h = +0.1 と −0.1 のそれぞれで、3位置の nll = logsumexp − logit_正解 を計算し、平均して L(±h) を求めます。
4. 中心差分を計算し、−0.3373 と比べます（許容差 0.002 + 0.002·|解答| ≈ 0.0027）。

<details><summary>答え合わせ用の数値</summary>

- X2 の d0 列 = [−0.7357, 0.7135, 1.2963]
- h = +0.1：logits の鳴く列 = [−0.0736, 0.0714, 0.1296]、nll = [1.4527, 1.3276, 1.3054]、**L = 1.3619**
- h = −0.1：logits の鳴く列 = [0.0736, −0.0714, −0.1296]、nll = [1.4762, 1.3110, 1.5007]、**L = 1.4293**
- 中心差分 = (1.3619 − 1.4293)/0.2 = **−0.3370**（解析解 −0.3373 との差 3.5×10⁻⁴ で許容範囲内）

h の選び方（`numgrad_by_hand.py` の出力。右の列は L を小数4桁に丸めた＝手計算と同じ条件）：

| h | 中心差分 | 誤差 | 前進差分 | 誤差 | 4桁に丸めた中心差分 | 誤差 |
|---|---:|---:|---:|---:|---:|---:|
| 0.1 | −0.3372 | +1.1e−04 | −0.3300 | +7.4e−03 | −0.3370 | +3.5e−04 |
| 0.05 | −0.3373 | +2.7e−05 | −0.3337 | +3.7e−03 | −0.3370 | +3.5e−04 |
| 0.01 | −0.3373 | +1.1e−06 | −0.3366 | +7.3e−04 | −0.3350 | +2.3e−03 |
| 0.001 | −0.3373 | +1.1e−08 | −0.3373 | +7.3e−05 | −0.3500 | −1.3e−02 |

**手計算では h = 0.05〜0.1 の中心差分が最適**です（4桁に丸めても誤差 3.5×10⁻⁴。暗算しやすい 0.1 がおすすめ）。h = 0.001 では、4桁で持った L の引き算で桁が消え、誤差 1.3×10⁻² は許容差の約5倍になります。
勾配が負になるのは、dWout[d0, 鳴く] = Σ_t X2[t, d0]·dlogits[t, 鳴く] の3項のうち、正解が「鳴く」である位置2の項 1.2963 × (−0.2513)（4.5 と 6.1 の値）が支配的だからです。Wout[d0, 鳴く] を増やすと位置2の正解 logit が上がり、損失が下がります。
</details>

### M3 多ステップ学習と学習率スキャン

**何をするか**：本編と同じ1文・同じ初期値で、lr ∈ {0.25, 0.5, 1, 2, 4} で100ステップ学習させます。
さらに、1次近似 ΔL ≈ −lr·‖g‖²（7.2）がどの lr から外れるか、lr を上げると本当に発散するかを調べます。

**なぜ理解が深まるか**：手計算の1ステップは学習の「1コマ」にすぎません。損失曲線、1次近似の有効範囲、発散の境目を見ると、
lr = 1 という本編の設定がどれくらい「攻めた」値なのか、そして学習率がなぜ最重要のハイパーパラメータなのかが分かります。

**手 / コード・時間**：コード、30分

**実行**：

```bash
python3 mini_gpt.py --train 100 --lr 0.25    # 損失と予測の推移（lr を 0.5, 1, 2, 4 に変えて繰り返す）
python3 extras/lr_scan.py                    # 上をまとめた表と、1次近似・発散の調査
```

**1次近似はどこで外れるか**（[2]、‖g‖² = 1.4701）

| lr | 予測 ΔL | 実際 ΔL | 実際/予測 | 予測した L' |
|---:|---:|---:|---:|---:|
| 0.01 | −0.0147 | −0.0147 | 1.003 | 1.3802 |

- lr ≤ 0.5 では誤差 8% 以内。lr = 1（本編）で 12% ずれ、lr = 2 では半分しか当たりません。

- 小さい lr で実際の方が少し**多く**下がるのは、勾配方向に沿った曲率 d²L/dη² = −0.8270 が負だから（出発点付近では、勾配方向に見た損失が上に凸）です。

**発散の境目**（[3] 最初の勾配方向に沿った損失 L(θ − η·g)、[4] 実際の学習）

| η | 0 | 0.5 | 1 | 2 | 4 | 6 | 8 | 9 | 10 | 12 | 16 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|

- lr = 8：1.3949 → 0.0002 → 0.0002 → **0.0069**（一度跳ねる）→ 0.0001 → 3.1e−14 と、揺れながらも収束しました。
- lr = 9：1.3949 → 0.0491 → **92.2579** → 9.2e+06 → 4.4e+16 … と**発散**。lr = 10, 16 も発散しました。
- `mini_gpt.py` と `lr_scan.py` は nll = logsumexp − logit で計算しているので、発散しても有限の値が出ます（`python3 mini_gpt.py --train 7 --lr 9`。さらに続けると重みそのものがオーバーフローして nan になります）。
  素直に −log(softmax) で計算すると、step 3 以降は正解の確率が 0 にアンダーフローして `inf` になります（本編ルール2「損失は logsumexp − logit で」の理由）。
</details>

### M4 mini_gpt.py を見ずに自分で実装する

**何をするか**：README §2〜3 の仕様と [`derivations.md`](../workbook/derivations.md) の式だけを見て、順伝播・逆伝播・SGD を自分で書き、[`answers.md`](../workbook/answers.md) と全チェックポイントで一致させます。

**なぜ理解が深まるか**：手計算では「次にどの表を埋めるか」が手順書に書いてありますが、実装ではそれを自分で決めなければなりません。
行列の形、転置、分岐での勾配の足し合わせを、もう一度自分の頭で組み立てることになります。手計算とコードの両方で同じ数字が出れば、理解は本物です。

**手 / コード・時間**：コード、4〜8時間（参考：mini_gpt.py の計算部分は、空行とコメントを除いて約100行）

**進め方**：

1. **順伝播**だけ書き、2.1〜5.3 を answers.md と照合します。L = 1.3949 になれば成功です。
2. **逆伝播**を書き、6.1〜6.9 を照合します。
3. **数値微分で検算**します。全180個のパラメータを ±10⁻⁶ ずつ動かして中心差分をとり、逆伝播と比べます。正しければ最大誤差は 10⁻¹⁰ 程度です（`python3 mini_gpt.py --gradcheck` の値は 1.5〜2.7×10⁻¹⁰）。
4. **SGD** を書き、L' = 0.1056 と予測の反転（`<s> <s> 。` → `猫 が 鳴く`）を確認します。
5. 余力があれば、バッチ（複数文）と任意の長さに対応させ、[`general_model.py`](general_model.py) と比べます。

**落とし穴**：仕様の細部が答えを変えます。LN は**母分散（÷4）**で ε = 0、ヘッド h は Q, K, V の**列 2h, 2h+1**、損失は3位置の**平均**、マスクは −∞、行ベクトル規約（X @ W）です。

**詰まったら**：`python3 extras/bug_signatures.py` は、mini_gpt.py にわざと1か所バグを入れて、**最初にずれるチェックポイント**と L, L' を表示します。
自分の実装の「最初にずれた場所」とこの表を見比べると、原因の見当がつきます。

<details><summary>実際の結果（bug_signatures.py）</summary>

正解は L = 1.3949、L' = 0.1056。

| バグ | 最初にずれるチェックポイント | L | L' |
|---|---|---:|---:|
| LN の分散を ÷3（不偏分散）にした | 2.2 μ, σ², σ | 1.4042 | 0.2396 |
| スコアを √d_k で割り忘れた | 3.2 S0 | 1.4070 | 0.1560 |
| Attention の softmax を列方向にとった | 3.3 A0 | 1.3203 | 0.4101 |
| 因果マスクを付け忘れた | 3.3 A0 | 1.3476 | 2.1457 |
| 損失を平均でなく和にした（dlogits の ÷3 忘れ） | 6.1 dlogits | 1.3949 | **0.0002** |
| 残差の分岐で勾配を足し忘れた（dX1 = LN2経由だけ） | 6.3 dX1 | 1.3949 | 0.6496 |
| LN の逆伝播で平均の2項を忘れた（dx = dy/σ） | 6.3 LN2経由 | 1.3949 | 0.1159 |
| dV = A dO と転置を忘れた | 6.6 dV0 | 1.3949 | 0.1034 |
| dK = dS Q と転置を忘れた | 6.6 dK0 | 1.3949 | 0.2523 |
| dQ, dK の 1/√d_k を忘れた | 6.6 dQ0 | 1.3949 | **0.0946** |
| SGD の符号を逆にした（θ + lr·g） | 7.1 E' | 1.3949 | 2.3983 |

**「L' が下がったから実装は正しい」とは言えません**。÷3 を忘れると勾配が3倍（= lr を3倍にしたのと同じ）になり、L' は 0.0002 と正解より**下がります**。
1/√d_k を忘れたときも 0.0946 と正解より低くなります。逆伝播の正しさは、数値微分とチェックポイントの照合で確かめてください。
</details>

### S1 因果マスクを外す：カンニングと生成の破綻

**何をするか**：因果マスクを外して学習させ、(1) 学習損失、(2) `<s>` から1語ずつ貪欲生成したときの文、(3) 位置0の出力が後ろの語に影響されるか、をマスクありと比べます。

**なぜ理解が深まるか**：学習時は3語を一度に入れるので、マスクが無いと位置0は「自分が当てるべき答え（位置1の語）」を見られます。
ところが生成時は1語ずつ入力するので、その「未来」はまだありません。**マスクは「生成時と同じ条件で学習させる」ための仕掛け**だと分かります。

**手 / コード・時間**：コード、30分（約20秒で終わります）

**実行**：`python3 extras/no_mask.py`

<details><summary>実際の結果</summary>

**2文タスク**（M1 と同じデータ、seed 0〜9）

| | 学習損失 | `<s>` から生成した文が正しい（猫 が 鳴く / 犬 が 吠える） |
|---|---|---:|
| マスクあり | 9 seed が 0.2311（下限 0.2310）、seed 8 のみ 0.4621 | **9/10** |
| マスクなし | 10 seed すべて **0.0000**（マスクありでは越えられない下限を下回る） | **3/10** |

マスクなしで生成された文の例：`鳴く が 鳴く`、`犬 吠える 吠える`、`が 猫 が`、`猫 犬 犬`。

**seed 0 の中身**：マスクなしのモデルの位置0は、ヘッド0 で位置1（猫/犬）を 0.993（文0）/ 1.000（文1）の重みで見ています。まさにカンニングです。

| | 3語まとめて入力したときの位置0の P(猫), P(犬) | `<s>` だけ入力したとき |
|---|---|---|
| マスクあり（文0・文1とも） | (0.500, 0.500) | (0.500, 0.500) |
| マスクなし・文0 | (1.000, 0.000) | (0.305, 0.000) |

### S2 自己回帰生成と KV キャッシュ

**何をするか**：手計算で求めた1ステップ更新後の重み（7.1）を使って、`<s>` から1語ずつ貪欲生成します。
毎回全部を計算し直す方法と、過去の K, V を使い回す方法（KV キャッシュ）で logits が一致することを確かめます。

**なぜ理解が深まるか**：因果マスクのおかげで、位置 t の出力は位置 0..t の入力だけで決まり、後ろに語を足しても変わりません（S1 で確認）。
だから過去の K, V は一度計算すれば使い回せます。新しい位置では q, k, v を1行だけ計算し、キャッシュ内の全 K とスコアをとるだけで済み、**マスクも要りません**（キャッシュには過去しか入っていないので）。
実際の LLM の推論が速い理由と、文脈長の上限がどこから来るかが分かります。

**手 / コード・時間**：コード 30分＋手 15分。手では、本編の 3.2〜3.4 の位置2の行の計算が「キャッシュ済みの K, V の0〜2行と、新しい q の1行」だけを使っていることを、自分の計算用紙で確かめてください。

**実行**：`python3 extras/kv_cache.py`

### S3 ロジット分解：更新で「誰が」正解を押し上げたか

**何をするか**：logits を「直接経路 X0 / ヘッド0 / ヘッド1 / FFN」の寄与に分け、更新前と更新後で比べます。

**なぜ理解が深まるか**：このモデルには最終 LN が無いので、logits = (X0 + ヘッド0 + ヘッド1 + F)·Wout が**厳密に**4つの和に分かれます（README §2 の設計判断）。
1ステップの更新で、どの部品がどの位置の正解を押し上げたのかが分かります。これは機械的解釈可能性（mechanistic interpretability）の入口でもあります。

softmax は全 logit に同じ数を足しても変わらないので、意味があるのは「正解が他よりどれだけ高いか」です。
そこで「中心化ロジット = 正解の logit − 5語の logit の平均」も分解しています（平均は線形なので、これも厳密に4つの和になります）。

**手 / コード・時間**：コード＋表の読み解き、30分。更新前の行列全体は `python3 mini_gpt.py --decompose` でも見られます。

**実行**：`python3 extras/decompose_update.py`

### S4 なぜ √d_k で割るのか

**何をするか**：(手) q, k の各成分が平均0・分散1で独立なとき、Var(q·k) = d_k を導きます。
(コード) 乱数の q, k（キー16個）で、d_k ∈ {2, 16, 128, 1024} について、√d_k で割る / 割らないで Attention の形を比べます。

**なぜ理解が深まるか**：本編は d_k = 2 なので、√2 ≈ 1.41 倍の違いしかなく、スケーリングの意味が実感しにくいです。
実際の LLM は d_k = 64〜128 なので、割らないと softmax がほぼ one-hot に張り付き、勾配も消えます。

**手 / コード・時間**：手 15分＋コード 15分

**実行**：`python3 extras/scaling.py`

<details><summary>導出</summary>

$q\cdot k = \sum_{i=1}^{d_k} q_i k_i$。各項は平均 $E[q_i]E[k_i] = 0$、分散 $E[q_i^2]E[k_i^2] = 1$ で、項どうしは独立。
よって $\mathrm{Var}(q\cdot k) = d_k$、標準偏差は $\sqrt{d_k}$。$\sqrt{d_k}$ で割れば標準偏差は $d_k$ によらず 1 になります。
</details>

<details><summary>実際の結果</summary>

キー16個、試行2000回の平均。一様分布のエントロピーは log 16 = 2.773。「1 − Σa²」は softmax の勾配の大きさの目安（= Σᵢ ∂aᵢ/∂sᵢ、one-hot なら 0）。

| d_k | 割り方 | スコアの標準偏差 | エントロピー | 最大の重み | 1 − Σa² |
|---:|---|---:|---:|---:|---:|
| 2 | そのまま | 1.402 | 2.156 | 0.305 | 0.808 |
| 2 | ÷√d_k | 0.992 | 2.405 | 0.223 | 0.870 |
| 16 | そのまま | 4.045 | 0.895 | 0.685 | 0.427 |
| 16 | ÷√d_k | 0.994 | 2.370 | 0.241 | 0.869 |
| 128 | そのまま | 11.291 | 0.284 | 0.888 | 0.158 |
| 128 | ÷√d_k | 0.998 | 2.358 | 0.248 | 0.867 |
| 1024 | そのまま | 31.870 | 0.099 | 0.959 | 0.059 |
| 1024 | ÷√d_k | 1.004 | 2.347 | 0.252 | 0.864 |

割らない場合、スコアの標準偏差は √d_k（1.41, 4, 11.3, 32）どおりに増え、d_k = 1024 では最大の重みが 0.959（ほぼ one-hot）、勾配の目安は 0.059 まで落ちます。
割れば、どの d_k でもほぼ同じ形（エントロピー 2.35〜2.41）に保たれます。
</details>

  本編の「全成分 ±1」は失われます。Q, K, V の計算（144回の積和）がすべて小数の掛け算になります。
- RoPE（d_k = 4、θ = 1, 1/100、乱数の q, k）：スコアは (m, n) = (0, 1), (5, 6), (100, 101) ですべて 0.888807、(0, 3), (7, 10) ですべて 1.037486。
  回転してもベクトルの長さは変わりません（|q| = |R₅q| = 0.674096）。
</details>

<details><summary>RoPE の性質の導出（ヒント）</summary>

2次元で $R(\alpha) = \begin{pmatrix}\cos\alpha & -\sin\alpha\\ \sin\alpha & \cos\alpha\end{pmatrix}$ とすると $R(\alpha)^\top = R(-\alpha)$、$R(\alpha)R(\beta) = R(\alpha+\beta)$。
よって $(R(m\theta)q)^\top (R(n\theta)k) = q^\top R(-m\theta)R(n\theta)k = q^\top R((n-m)\theta)\,k$。
</details>

### C3 重み共有 Wout = Eᵀ

**何をするか**：出力層を埋め込みの転置にしたモデル（GPT-2 などと同じ）で、E の勾配が2つの経路の和
$dE_{\text{共有}} = dE_{\text{入力側}}\,(6.9) + dW_{\text{out}}^\top\,(6.1)$ になることを導き、数値微分で確かめます。共有あり / なしで学習も比べます。

**なぜ理解が深まるか**：derivations.md 問2「分岐したら勾配を足す」の、パラメータ版です。
本編では入力に出てこない 鳴く・。 の dE 行は 0 でしたが（6.9）、共有すると出力側から勾配が届き、これらの埋め込みも学習され始めます。

**手 / コード・時間**：手 20分（導出）＋コード 10分

**実行**：`python3 extras/weight_tying.py`

### C4 2層で生まれる induction head（読むだけ）

**何をするか**：「…A B … A」のあとに B を予測する仕組み（induction head）が、**2層の Attention の合成**で生まれることを読みます。

**なぜ理解が深まるか**：1層目の「1つ前のトークンを見る」ヘッド（previous-token head）が「直前は A だった」という情報を各位置に書き込み、
2層目のヘッドがそれをキーにして「直前が A だった位置」を探し、その位置のトークン B をコピーします（K-composition）。
本編の1層モデルではこれができないことと、残差ストリームが「層をまたぐ通信路」であることが分かります。
C1 の `pre_post_ln.py` で学習させた「1つ前のトークンを答える」タスクは、この前半（previous-token head）にあたります。

**手 / コード・時間**：読む、1〜2時間。実装するなら `pre_post_ln.py` の2層 Pre-LN モデルに「A B … A → B」型のランダム系列を学習させるのが近道です（このリポジトリでは未実装）。

**参考**：Elhage et al.「A Mathematical Framework for Transformer Circuits」(2021)、Olsson et al.「In-context Learning and Induction Heads」(2022)。

### C6 2つのヘッドを同じ初期値にする（対称性）

**何をするか**：ヘッド1 の Wq, Wk, Wv の列と Wo の行をヘッド0 のコピーにして学習させます。

**なぜ理解が深まるか**：2つのヘッドは順伝播で同じ出力を出し、逆伝播でも同じ勾配を受け取るので、**何ステップ学習しても同一のまま**です。
マルチヘッドが別々のことを学べるのは、初期値がランダム（非対称）だからだと分かります。

**手 / コード・時間**：コード、15分

**実行**：`python3 extras/symmetry.py`

<details><summary>実際の結果</summary>

| 0（完全に同じ） | 差 0、Attention 重みの差 0 | 差 0、0 | 差 0、0 |
| 1.3×10⁻³（少しずらす） | 差 2.0×10⁻³、7.7×10⁻⁴ | 2.0×10⁻³、8.4×10⁻⁴ | 1.9×10⁻³、1.1×10⁻³ |

完全に同じなら、1000ステップ後も差は厳密に 0 です。少しずらしても、このタスクは1ヘッドで足りるので差はほとんど広がりません。

## 学べないこと（盲点）と補い方

このワークブックは「1ステップの計算と勾配の流れ」を理解するためのものです。次のことは、設計上ほとんど学べません。
数値は `python3 extras/blind_spots.py` の出力です（C1, S6 の結果も引用しています）。

| 盲点 | このワークブックでは | 実際には / 確かめた事実 | 補い方 |
|---|---|---|---|
| **汎化** | 1文を覚えるだけ。学習データ = 評価データ | 100ステップ学習後のモデルは、`<s> 鳴く 。` にも `<s> 。 。` にも「猫 が 鳴く」と答えた（確率 0.98〜1.00）。**語より位置で覚えている**（`<s> が 猫` では位置2の答えが「が」に変わるので、位置だけでもない）。1文だけでは、どちらの規則が正しいか区別できない | 学習に使っていない文で評価する。M1（2文）、C5（実データ） |
| **最適化（Adam・warmup）** | 素の SGD、lr = 1 | Adam の1歩目は、勾配が 1.3×10⁻⁶〜0.398 と大きく違っても、更新量 \|Δθ\|/lr が 0.9926〜1.0000 とほぼ同じ。Post-LN は warmup なしだと学習できなかった（C1） | S6（AdamW）、C1（warmup） |
| **初期化のスケール** | 0.5 刻みの手作りの重み | 本編のタスクで N(0, 0.02²) に初期化すると、初期損失 1.6095（≈ ln5 = 1.6094）、位置2の注意の最大値 0.3338（≈ 一様の 0.3333）。N(0, 0.5²) だと 1.9694 と 0.5699。本編の重み（1.3949、0.7425）は「最初から少し偏った」特別な出発点 | GPT-2 / nanoGPT の初期化（標準偏差 0.02）を読む。C1 の初期化の比較 |
