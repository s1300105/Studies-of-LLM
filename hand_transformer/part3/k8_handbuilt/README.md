# K8 重みを手で決めて induction head を作る（任意、2時間）

K7 では、勾配降下が induction head を**見つける**ところを見ました。K8 では逆に、2層の Attention-only Transformer の重みを**自分で決めて**、
同じ働きをするモデルを作ります。学習は一切しません。

考え方は RASP（Weiss et al. 2021）と tracr（Lindner et al. 2023）と同じです：**残差ストリームをいくつかの「区画」（部分空間）に分け、各区画を1つの変数として使う**。
ヘッドは「ある区画を読んで、どこを見るかを決め、見た所の別の区画を、また別の区画に書く」という操作になります。
重みの1つ1つに「なぜこの値か」を言えるモデルを一度作っておくと、K7 で学習した重みを読むとき（K7 §5.4）に何を探せばよいかが分かります。

> **はじめ方（5分）**
> 1. K7 を先に終えておく（モデルの式とデータの形は [`../k7_induction/README.md`](../k7_induction/README.md) §1〜§2 と同じ）
> 2. このフォルダ `hand_transformer/part3/k8_handbuilt/` で `python3 check.py my_weights.py` を実行する（全部 0 の重みなので未達）
> 3. [`my_weights.py`](my_weights.py) の TODO を、下の手順1〜5の順に埋める。1つ埋めるたびに `check.py` を回す
>
> 数値はすべて、このフォルダのスクリプトを実行して得た出力です（Python 3.13.17 / NumPy 2.5.3）。

## 1. 約束

順伝播は K7 の `attn_only.py` そのものです（LayerNorm・FFN・バイアスなし）。

$$X_0 = E[\text{ids}] + P,\qquad
X \leftarrow X + \operatorname{softmax}\!\Big(\frac{(X W_q)(X W_k)^\top}{\sqrt{d_k}} + \text{マスク}\Big)(X W_v)\,W_o \ \ (\text{層ごと}),\qquad
\text{logits} = X W_\text{out}$$

- トークン番号：0〜15 が内容、16 が `<s>`、17 が `<pad>`（語彙 nv = 18）。T = 21。
- ヘッドごとに $d_k$（$W_q, W_k$ の列数）と $d_v$（$W_v$ の列数 = $W_o$ の行数）を自由に決めてよい。
- **スコアは $\sqrt{d_k}$ で割られる**ので、点差 s が欲しければ $W_q$ を $s\sqrt{d_k}$ 倍しておく。

## 2. 手順

### 手順1 区画を決める

ひな形はこう分けてあります（D = 18 + 21 + 18 + 18 = 75）。

| 区画 | 次元 | 中身 | 書く人 | 読む人 |
|---|---|---|---|---|
| TOK | 0〜17 | 今のトークンの one-hot | E | 層0 の値、層1 のクエリと値 |
| POS | 18〜38 | 今の位置の one-hot | P | 層0 のクエリとキー |
| PREV | 39〜56 | 1つ前のトークンの one-hot | 層0 のヘッド | 層1 のキー |
| OUT | 57〜74 | 答え（コピー元のトークン） | 層1 のヘッド | Wout |

区画を分けるのは、**書き込みどうしが混ざらない**ようにするためです。たとえば PREV を TOK と同じ次元に書くと、層1 のキーが「今のトークン」と「1つ前のトークン」の和になり、照合がずれます。
K7 の学習済みモデルは d_model 32 しか使っていません。学習では、区画をきっちり分ける代わりに、ほぼ直交する方向に詰め込みます。

### 手順2 E と P

E の行 t の TOK 区画の t 番目を 1、P の行 i の POS 区画の i 番目を 1 にします。これで $X_0$ の各行は「トークンの one-hot」と「位置の one-hot」を並べたものになります。

### 手順3 層0：previous-token head

- **QK**：クエリ位置 i とキー位置 j の内積が「j = i − 1 のときだけ s₀、それ以外は 0」になるようにする。
  POS 区画から、クエリは $u_i$（$d_k$ = T 次元の one-hot）、キーは $u_{j+1}$ を作れば、内積は $[j + 1 = i]$ です。
- **OV**：値は TOK 区画をそのまま読み（$d_v$ = 18）、出力は PREV 区画に書く。
- 点差 s₀ はどれくらい要るか：正しいキー以外に最大 20 個のキーがあるので、正しいキーの重みは $e^{s_0}/(e^{s_0} + 20)$ 以上です。
  0.999 以上にするには $s_0 \ge \ln(20 \times 999) = 9.90$。参考解は s₀ = 10（重み 0.99909 以上）にしました。

ここまで書いて `check.py` を回すと、まだ acc_2nd は低いままですが、「層0 ヘッド0: prev」が 1 に近づくはずです。

### 手順4 層1：induction head

- **QK**：クエリは TOK 区画（今のトークン a）、キーは PREV 区画（その位置の1つ前のトークン b）を読み、内積が $s_1[a = b]$ になるようにする（$d_k$ = 18）。
  2回目の S[k] から見ると、一致するキーは1回目の S[k] の**次の位置**（コピー元）だけです（もう1つの候補 = 2回目の S[k] の次は、未来なのでマスクされる）。
- **OV**：値は TOK 区画を読み、出力は OUT 区画に書く。

### 手順5 Wout と採点

OUT 区画のトークン t を logit の t 列に s₂ 倍で写します。ほかの区画は Wout で読まない（TOK を読むと「今のトークン」も出力に混ざる）。

```bash
python3 check.py my_weights.py
```

## 3. 考える問い

<details><summary>Q1. 参考解の loss_1st は 4.7612 で、当て推量（ln 18 = 2.8904）より悪い。なぜか。どう直すか</summary>

1回目では、層1 のクエリに一致するキーが無いので、スコアは全部 0 になり、**見えている位置すべてを一様に**見ます。すると「既に出たトークン」を一様にコピーして、その logit が上がります。
しかし1回目の正解は「まだ出ていないトークン」なので、自信を持って間違えます。

直し方の1つ：一致が無いときは `<s>`（位置0）を見るようにして、`<s>` をコピーしたら何も出さない（Wout の `<s>` の行を 0 にする）。
層1 のキーに1次元足して、どのクエリも位置0 とだけ s₁/2 点で合うようにします（一致すれば s₁ が勝つ）。`solution.py` の `sink=True` がこれです：

```bash
python3 check.py solution.py --sink
```

loss_1st 2.8961、loss_2nd 0.0008、acc_2nd 1.0000、層1 ヘッド0 の bos 0.527。K7 の学習済みの induction head も、1回目は `<s>` を見ていました（K7 §5.2 の例で、位置1〜5 から `<s>` へ 0.86〜1.00）。
学習は同じ工夫（attention sink）を自分で見つけていたことになります。
</details>

<details><summary>Q2. 層0 ヘッド0 を消すと acc_2nd はちょうど 0.0000 になる。0.06（当て推量）ではなく 0 になるのはなぜか</summary>

PREV 区画が空になるので、層1 のキーは全部 0、スコアも全部 0 で、層1 は見えている位置を一様に見ます。2回目の S[k] の位置では、S[0]〜S[k] は**2回ずつ**、正解の S[k+1] は**1回**しか出ていません。
一様にコピーすると2回出たトークンの logit が一番大きくなるので、正解が argmax になることは**一度もありません**。
</details>

<details><summary>Q3. 点差 s₀ = s₁ = s₂ を 1, 2, 3, 5, 10, 20 と変えると、loss_2nd と acc_2nd はどうなるか（予想してから solution.py の S0, S1, S2 を書き換えて確かめる）</summary>

| s | loss_2nd | acc_2nd | loss_1st | 層0 の prev | 層1 の ind |
|---:|---:|---:|---:|---:|---:|
| 1 | 2.8320 | **0.0000** | 2.9388 | 0.331 | 0.116 |
| 2 | 2.5480 | **1.0000** | 3.0140 | 0.543 | 0.232 |
| 3 | 1.6781 | 1.0000 | 3.1278 | 0.746 | 0.490 |
| 5 | 0.1671 | 1.0000 | 3.4828 | 0.952 | 0.915 |
| 10 | 0.0008 | 1.0000 | 4.7612 | 1.000 | 0.999 |
| 20 | 0.0000 | 1.0000 | 7.7923 | 1.000 | 1.000 |

s = 2 で argmax はもう全部当たりますが、loss_2nd は 2.5480 と当て推量に近いままです（`check.py` は「確率は低い」と注意を出します）。**正解率と損失は別のものを測っています**。
s = 1 で acc_2nd が 0 になるのは Q2 と同じ理由です（注意がほぼ一様になる）。逆に s を大きくすると loss_2nd は 0 に近づきますが、Q1 の問題（1回目の自信過剰）は悪化します。

1つだけ s = 1 にした場合（ほかは 10）：s₀ だけ → loss_2nd 0.2258、s₁ だけ → 1.6832、s₂ だけ → 1.9820（acc_2nd はどれも 1.0000）。
</details>

<details><summary>Q4. 1層・1ヘッドで、N = 8 に固定したデータを解く重みを作れるか。N = 4〜10 が混ざったデータではどうなるか</summary>

作れます。2回目の位置 i の答えはいつも位置 i − 7 のトークンなので、手順3 の previous-token head のずれを 1 から N − 1 = 7 に変え、値を TOK から OUT へ直接コピーするだけです（PREV 区画は要らない）。

```bash
python3 check.py solution_1layer_fixed.py --fixed-n 8                 # N = 8 だけのデータ
python3 check.py solution_1layer_fixed.py --fixed-n 8 --eval-varied   # 同じ重みを N = 4〜10 のデータで
```

N = 8 だけなら acc_2nd 1.0000、loss_2nd 0.0008。N が混ざると acc_2nd 0.1644 で、内訳は N = 8 だけが 1.000、ほかの N はすべて 0.000 です。
トークンの中身を照合していないので、N が変わると全く当たりません。K7 で N を系列ごとに変えたのは、この近道を閉じるためです（K7 §6.3）。
</details>

<details><summary>Q5. 1層で、N が混ざったデータを解く重みは作れるか</summary>

作れません。キー位置 j の行には、1層目の時点で「位置 j のトークン」と「位置 j」しか入っていないので、「1つ前のトークンが今のトークンと同じ位置」をスコアで選べません（K7 §6.1）。
1つ前のトークンを位置 j に運ぶために、Attention がもう1回（層0 の previous-token head）要ります。
</details>

<details><summary>Q6. RASP で書くとどうなるか</summary>

RASP では、Attention 1回 = select（どのキーを見るか）＋ aggregate（見た所の値を集める）です。擬似コードで書くと：

```
prev = aggregate(select(indices, indices, key == query − 1), tokens)    # 層0：1つ前のトークン
out  = aggregate(select(prev,    tokens,  key == query),     tokens)    # 層1：1つ前が今と同じ位置のトークン
```

tracr はこのようなプログラムを、変数ごとに残差ストリームの部分空間を割り当てて Transformer の重みに「コンパイル」します。手順1〜5 でやったことを自動化したものです。
</details>
