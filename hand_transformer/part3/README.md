## K1 スカラー自動微分（3h）

**何をするか**：1つ1つの数をノードにした自動微分 `Value` を書きます（Karpathy の micrograd と同じ設計）。
骨組み [`k1_autograd/value.py`](k1_autograd/value.py) の TODO は6か所：`*`・定数乗 `**k`・`exp`・`log`・`relu` の局所微分と、`backward()`（トポロジカル順に並べて、出力側から `_backward` を呼ぶ）。`+` は見本として実装済みです。

**なぜ理解が深まるか**：Part 1 のステップ6 で「下から上へ」解いた順番は、計算グラフのトポロジカル順の逆そのものです。
分岐で勾配を足す規則（Part 0 D2、derivations.md 問2）は、コードでは `self.grad += …` の `+=` 1文字になります。手で8時間かけた逆伝播が、30行ほどの規則の機械的なくり返しだと分かります。

**時間の内訳**：骨組みと micrograd の設計を読む 0.5h、5つの演算 1h、`backward` 0.5h、テストを通す 0.5h、予想と振り返り 0.5h

**進め方**：

1. 書く前に「予想しよう」に答える
2. `*` から順に TODO を埋め、そのつど `python3 test_value.py` を回す（「1. 基本演算」の行が上から OK になっていく）
3. `backward` を書き、「2. ランダムな式」を通す。テストは、乱数で作った式（DAG、同じノードを何度も使う）500 個について、自動微分の勾配を 50 桁の十進演算による中心差分と比べます
4. 余力があれば「3. 深い鎖」（任意）も通す（再帰で書くと RecursionError になる）

**予想しよう**（答えは「実際の結果」の中）

1. `__mul__` の `_backward` で `self.grad += …` を `self.grad = …` にすると、`a * a` の勾配は正しく出るか。`e = a·b; e + e·e` はどうか
2. `backward` でノードを「逆順」ではなく「トポロジカル順のまま」たどると、何が起きるか
3. Part 1 の順伝播（2.1〜5.3）を `Value` で組むと、ノードはいくつになるか。手計算の積の回数（1回目の順伝播で、工夫なしなら 540 回）と比べて多いか少ないか

**マイルストーン**：`python3 test_value.py` で「1.」が全部 OK、「2.」の最大誤差 ≤ 1e-8

<details><summary>実際の結果（参考解答 <code>python3 test_value.py --ref</code> と、わざとバグを入れた版）</summary>

- 参考解答：ランダムな式 500 個（ノード数の合計 6,521）で最大誤差 3.6×10⁻¹⁵。`--n 3000 --seed 1`（38,400 ノード）でも 1.4×10⁻¹⁴。深い鎖も OK
- 予想1：`__mul__` の1行目だけを `=` にした版では、`a * a` は**正しく出ます**（2行目の `other.grad += …` が同じオブジェクトに足すので）。しかし `e = a·b; e + e·e` は勾配 [1.0, 4.0]（正解 [1.5, 6.0]）、ランダムな式の最大誤差は 2.3×10² になります。**+= の誤りは、分岐が重なったときにだけ見える**
- 予想2：トポロジカル順のままたどると、`_backward` を呼ぶ時点で上流の勾配がまだ 0 なので、ほとんどの勾配が 0 になります（`e + e·e` で [0.0, 0.0]、最大誤差 1.0）
- そのほか：`pow` の係数 k を忘れると最大誤差 3.8×10¹、`log` の微分を 1/x でなく x にすると 3.1×10²
- 予想3 の答えは K2 で出ます
- `backward` を再帰で書いた版は、テスト1・2 と K2 は通り、テスト3（5,001 項の鎖）だけ RecursionError になります
</details>

## K2 Part 1 をスカラー自動微分で再検証（1h）

**何をするか**：Part 1 の順伝播（2.1〜5.3）を `Value` だけで組み立て、`loss.backward()` の 180 個の勾配を `mini_gpt.py`（＝手計算の正解）と照合します。続けて SGD（lr = 1）で更新し、もう一度 `Value` で順伝播して L' = 0.1056 を再現します。
組み立てるコードは [`k2_verify_part1.py`](k2_verify_part1.py) の `forward`（約30行）にあります。腕に自信があれば、これを見ずに自分で書いて置き換えてもかまいません。

```bash
python3 part3/k2_verify_part1.py            # 参考解答の Value で
python3 part3/k2_verify_part1.py --mine     # 自分の part3/k1_autograd/value.py で（これが本番）
python3 part3/k2_verify_part1.py --part 2   # Part 2（2文・6行・ブロック対角マスク、188 個）でも同じことをする
```

**なぜ理解が深まるか**：`forward` の各行を Part 1 のチェックポイント番号に対応づけて読むと、行列の式（mini_gpt.py）と手計算の1マス1マスの中間の粒度で、モデル全体をもう一度たどることになります。
そして、自動微分は「どの積が 0 か」を知らないので、手計算で飛ばした積もすべてノードとして作られることが、数で分かります。

**進め方**：`forward` を読み、各行の右端のチェックポイント番号を確かめる（20分）→ ノード数を予想する（K1 の予想3）→ `--mine` で実行（10分）→ ノード数と手計算の積の回数を比べ、違いの理由を書く（20分）→ `--part 2` でも実行（10分）

**マイルストーン**：`--mine` で「全 180 個の最大誤差 … OK（≤ 1e-10）」と「L' = 0.1056 … OK」

<details><summary>実際の結果（<code>python3 part3/k2_verify_part1.py</code>、<code>--part 2</code>）</summary>

| | Part 1 | Part 2 |
|---|---:|---:|
| L（Value と mini_gpt の差） | 1.3949（差 0） | 1.3507（差 0） |
| 勾配の数・最大誤差 | 180 個・2.2×10⁻¹⁶ | 188 個・8.3×10⁻¹⁷ |
| SGD 1ステップ後の L' | **0.1056** | **0.5482** |
| グラフのノード数（深さ） | 1,448（79） | 2,797（83） |
| 積ノード | 580 | 1,183 |
| 　うち 0 との積 / ±1 との積 / それ以外 | 235 / 216 / 129 | 872 / 266 / 45 |

Part 1 のノードの内訳：`*` 580、`+` 518、葉（パラメータ・定数）254、`exp` 27、`**2` 24、`relu` 24、`**-1` 12、`**0.5` 6、`log` 3。

- 手計算（README §5、`cost.md`）では、1回目の順伝播の積は工夫なしで 540 回、0 との積など計算不要の 258 回を飛ばして、実際に掛けたのは 282 回でした。`Value` のグラフは、LN の ÷4、スコアの ÷√2、softmax の正規化なども積ノードにするので 580 個になり、**0 との積 235 個も律儀に作ります**。手計算の工夫（0 を見たら飛ばす、±1 なら符号を付けるだけ）は、汎用の自動微分にはありません
- Part 2 は2文を6行に積んだので、積ノードの大半（1,183 個中 872 個）が 0 との積です。Part 2 の重み（E は d0, d1 だけ、P は d2, d3 だけを使う）が、手計算をどれだけ軽くしているかの裏返しです
- `backward()` は、順伝播で作ったノードの `_backward` を1回ずつ呼ぶだけです（Part 1 で 1,448 回）。手で8時間かかった逆伝播が、この環境では数ミリ秒でした
- グラフの深さは 79 なので、再帰で書いた `backward` でも Python の再帰の上限（既定 1000）に届きません
</details>

## K3 行列レベルの自前実装（5h）

**何をするか**：**mini_gpt.py を見ずに**、README §2〜3（仕様と記号）と [`derivations.md`](../workbook/derivations.md)（逆伝播の式）だけを見て、順伝播・逆伝播・SGD を NumPy の行列で書きます（[発展課題 M4](../extras/README.md#m4-mini_gptpy-を見ずに自分で実装する) と同じ）。
次に、それを Part 2（2文を6行に積み、文をまたぐ注意も禁じたブロック対角のマスク）に一般化し、**Part 1・Part 2 の全チェックポイント**を照合スクリプトで突き合わせます。

骨組み [`k3_matrix/my_gpt.py`](k3_matrix/my_gpt.py) の冒頭に API が書いてあります。要点：

- `forward(p, task) -> c`：`task` は `{"inp", "tgt", "posi", "mask"}`（`mask[i, j] = True` は「行 i は行 j を見てはいけない」）。`c` に必須なのは `"loss"` と `"logits"` だけで、`"X0"`, `"ln1"`, `"U1"`, `"Q"`, `"S"`（ヘッドごとのリスト）… と README の記号どおりの名前で入れたものはすべて照合されます
- `backward(p, c) -> g` または `(g, d)`：`g` は9個のパラメータの勾配（必須）、`d` は中間変数の勾配（任意、`"logits"`, `"X1_ln2"`, `"A"` …）
- Part 2 の分析（任意）：`ablate_t2`（5.4）、`head_contributions`（5.5）、`qk_circuit`・`ov_circuit`（8.1）
- (B, T, …) のバッチ形式で返してもかまいません（照合スクリプトが N = B·T 行に並べ直します）

```bash
python3 part3/k3_check.py part3/k3_matrix/my_gpt.py --part 1     # まず Part 1
python3 part3/k3_check.py part3/k3_matrix/my_gpt.py              # Part 1 と Part 2
python3 part3/k3_check.py part3/k3_matrix/my_gpt.py -v           # 量ごとの誤差を全部表示
python3 part3/k3_check.py part3/k3_matrix/my_gpt.py --gradcheck  # 自分の forward だけで数値微分（正解を使わない検算）
python3 part3/k3_check.py part3/k3_matrix/my_gpt.py --autograd --value part3/k1_autograd/value.py   # K1 の自動微分と比べる
```

**なぜ理解が深まるか**：手計算では「次にどの表を埋めるか」が手順書に書いてありましたが、実装では形・転置・分岐での足し合わせを自分で決めなければなりません。
さらに Part 2 への一般化で、**「2文を積んでブロック対角のマスクをかける」ことが「バッチ次元を足す」ことと同じ**だと分かります。Part 1 では見えなかったバグ（下の表）が、ここで初めて表に出ます。

**進め方と時間**：

1. **順伝播（Part 1）** 1h：2.1〜5.3 が一致し、L = 1.3949 になる
2. **逆伝播（Part 1）** 1.5h：6.1〜6.9。最初にずれたチェックポイントの式を derivations.md で確かめる
3. **検算** 0.5h：`--gradcheck`（数値微分）と `--autograd`（K1 の `Value`）。数値微分の誤差は 1e-10 程度、自動微分との差は 1e-16 程度まで小さくなる、という違いも確かめる
4. **SGD と 7.x** 0.25h：L' = 0.1056
5. **Part 2 へ一般化** 1h：語彙 6、行数 N = 6、マスクは `task["mask"]` をそのまま使う、損失は ÷N、P の各行と E の `<s>`・`が` の行は2回ずつ使われる（勾配を足し込む）
6. **Part 2 の分析関数**（任意、余れば）：5.4・5.5・8.1 を自分のコードで再現する
7. **バグを3つ再現** 0.75h：[`../extras/bug_signatures.py`](../extras/bug_signatures.py) の表（Part 1）から3行を選び、自分のコードにそのバグを入れて、「最初にずれるチェックポイント」と L, L' が表と同じになることを確かめる

**Part 2 で初めて見えるバグ**（参考解答に1か所だけバグを入れて `k3_check.py` で確かめたもの。正解は L = 1.3507、L' = 0.5482）

| バグ | Part 1 | Part 2 で最初にずれる所 | Part 2 の L' |
|---|---|---|---:|
| `g["P"][posi] += dX0`（NumPy の重複インデックスは足し込まれない） | 全部一致 | 6.9 dP | 0.5936 |
| P の勾配を足し込まずに上書き（`g["P"][posi[row]] = dX0[row]`） | 全部一致 | 6.9 dP | 0.5799 |
| マスクを `np.triu` で自作（`task["mask"]` を使わない） | 全部一致 | 3.3 A0（L も 1.3300 にずれる） | 0.6328 |
| dlogits を ÷3 に固定（÷N のつもり） | 全部一致 | 6.1 dlogits | **0.3147** |

- Part 1 は `inp` にも `posi` にも重複が無いので、足し込みのバグは見えません。`np.add.at(g["P"], posi, dX0)` か、行ごとの `+=` のループで書きます
- ÷3 の固定は勾配が2倍（lr を2倍にしたのと同じ）になり、L' は正解より**下がります**。Part 1 の bug_signatures の表と同じく、「L' が下がったから正しい」とは言えません

**マイルストーン**：`k3_check.py` で Part 1・Part 2 とも「全チェックポイント一致」、`--gradcheck` の全体の最大誤差 ≤ 1e-9、bug_signatures の3行を再現

## K4 2文タスクの学習ダイナミクス（4h）

**何をするか**：Part 2 の初期値（`part2/params.json`）から、SGD と Adam で数百ステップ学習させ、毎ステップ次のものを記録します。

| 記録するもの | Part 2 のどこ | 意味 |
|---|---|---|
| L、C | 5.3、5.4 | 損失と、文脈の使い分け C = (鳴く − 吠える)@猫文 t2 − (同)@犬文 t2 |
| a0, a1 | 3.3 | ヘッド0・1 の 猫文 t2 → t1 の注意（犬文も同じになる） |
| パターン項・値項・直接効果・パッチングの総効果 | 5.5 | ヘッドごとに C へいくら寄与しているか |
| t2 のクエリの各キーへのスコア | 8.1 | QK 回路がどこを見ているか |
| 群の移植（readout = Wout、OV = Wv, Wo、QK = Wq, Wk） | 7.5 | step t の群 X だけを使い、残りは初期値のままにしたモデルの C と L。群 X が何を学んだかの目安 |

さらに、乱数の初期値（seed 0〜9）からも学習させ、損失の下限 $2\ln2/6 \approx 0.2310$ に届く seed と、文脈を使わない最善 $4\ln2/6 \approx 0.4621$（t0 と t2 がどちらも 50:50）で止まる seed を調べます。最後に「罠」を2つ試します。

**なぜ理解が深まるか**：Part 2 の1ステップで「C が 0 から 3.6937 に生まれる」ところまでは手で見ました。その先、C がどう育ち、2つのヘッドがどう役割を分け、どの部品が先に学ぶのかは、1ステップでは分かりません。
また、Part 2 の重みは「きれいに対称」に作ってありますが、乱数の初期値からでは同じように学べるとは限りません。

**進め方と時間**：

1. **予想を書く** 0.25h：下の「予想しよう」に答える
2. **学習ループ** 0.5h：SGD と Adam（β1 = 0.9, β2 = 0.999, ε = 10⁻⁸、バイアス補正あり、weight decay なし）

**予想しよう**

1. readout（Wout）・OV・QK のうち、どれが最初に動くか。どれが一番長くかけて育つか
2. Part 2 の1ステップでヘッド1 の寄与は −4.03 → −1.68 と縮みました。学習を続けると、ヘッド1 は「逆向きの情報を運ぶヘッド」のまま残るか

**マイルストーン**：「readout・OV・QK のどれが最初に立ち上がったか」を、自分の記録（グラフ）を根拠に1段落で答え、予想1 と比べる

**どれが先に動くか**（群の移植の値が、300 ステップ中の最大値の半分に初めて届いたステップ。readout は L の下がり幅、QK・OV は C）

readout は「文脈が要らない部分」（t1 → が、t0 と t2 の 50:50）で損失を先に下げ、QK が t1 を見る量を変え、OV が運ぶ中身を一番長くかけて育てます。

<details><summary>実際の結果 (2)：乱数の初期値（<code>--section seeds</code>）</summary>

全パラメータを N(0, 0.02²) で初期化（GPT-2 と同じ標準偏差）、3000 ステップ。

| | 床 0.2310 に届いた | プラトー 0.4621 で停滞 | プラトーに着いたステップ | 床に着いたステップ |
|---|---:|---:|---:|---:|
| SGD lr = 1 | 8（seed 2, 6 以外） | 2（seed 2, 6） | 36〜41 | 885〜2144 |
| Adam lr = 0.01 | 8（seed 4, 8 以外） | 2（seed 4, 8） | 40〜89 | 88〜1051 |

- どの seed も、まず40ステップ前後で**文脈を使わない最善 0.4621 に着き、そこで止まります**。停滞中の C は 10⁻⁶ 程度（seed 2 で 2.99×10⁻⁶）で、SGD の停滞 seed では t2 → t1 の注意は 0.333〜0.334（3つのキーにほぼ一様）
- C = (読み出しの向き) · (t2 の残差ストリームの2文の差) は2つの小さな量の積なので、両方が小さい所から始めると、どちらも育つきっかけが無い**鞍点**に長くとどまります。抜け出すまでの時間は seed しだいで大きく違います（予想4）
- `--steps 12000` では、SGD の seed 2 は 6726 ステップで床に届き、seed 6 は 12000 ステップでも 0.4622 のまま。Adam の seed 4, 8 は 3673, 3479 ステップで届き、10/10 になりました。「止まる」のではなく「とても長く待つ」です
- 初期化を大きくすると：N(0, 0.1²) では SGD・Adam とも 10/10 が床へ。N(0, 0.5²) では Adam は 10/10 が床へ、**SGD lr = 1 は 7/10 が発散（nan）**し、3/10 が床へ
- Part 2 の重みは、この鞍点を避けて「最初から2つのヘッドが情報を運んでいる（ただし打ち消し合っている）」状態に作ってあります。だから1ステップで C が生まれます
</details>

<details><summary>実際の結果 (3)：丸め誤差ほどの違いで結果は変わるか（<code>--section robust</code>）</summary>

初期値の全成分に 10⁻¹²·N(0, 1) を足して 20 回、300 ステップ。

| | 発散 | L | C | a1（ずらさない場合） |
|---|---:|---|---|---|
| SGD lr = 1 | 2/20 | 0.2316〜0.2338 | 16.9576〜18.8184 | 0.0930〜0.4187（0.2555） |
| SGD lr = 0.3 | 0/20 | 0.2323〜0.2325 | 15.6518〜15.6545 | 0.4076〜0.4077（0.4077） |
| Adam lr = 0.01 | 0/20 | 0.2312 | 18.0775〜20.0229 | 0.0129〜0.0703（0.3380） |

- SGD lr = 1 は安定性の縁にあり、10⁻¹² のずれで発散することがあります。自分の実装（足し算の順序が違えば丸め誤差も違う）で K4 を再現するときは、lr = 1 の step 20 以降は数字が合わなくても不思議ではありません。lr = 0.3 は C が 3〜4 桁まで再現します
- Adam は L はそろうのに、ヘッド1 の注意 a1 が 0.338 から 0.01〜0.07 に変わり、パターン項も最大 4.0×10⁻² になります。ずらさない Adam は鏡映対称性の上を進む特別な軌道で、わずかな非対称を Adam が増幅すると別の解（ヘッド1 が t1 をほとんど見ない）に行きます
</details>

<details><summary>実際の結果 (4)：罠（<code>--section trap</code>）</summary>

C = r · Δ（r = Wout[:,鳴く] − Wout[:,吠える]、Δ = X2[猫文 t2] − X2[犬文 t2]）。最終 LN が無いので厳密に成り立ちます。両方が 0 から始まったらどうなるか。

**(a) Wout の 鳴く列と 吠える列を同じにする**（両方を平均 [0.5, 0.5, 0, 1] に。SGD lr = 0.3）

| step | 0 | 1 | 2 | 20 | 300 |
|---|---:|---:|---:|---:|---:|
| C | 0 | **0** | 2.464×10⁻³ | 4.572 | 16.28 |
| \|r\| | 0 | 6.94×10⁻¹⁸ | 8.38×10⁻³ | 0.989 | 1.85 |
| \|Δ\| | 0 | 0.168 | 0.294 | 4.62 | 8.82 |

1ステップ目は r の勾配が Δ に比例するので r = 0 のまま（C = 0）ですが、その間に他の重みが動いて Δ ≠ 0 になり、2ステップ目から r も C も育ちます。300 ステップで L = 0.2320。**この罠は1ステップしか効きません**。

**(b) Wv = Wo = 0 にする**（Adam lr = 0.01）：Attention の出力は 0、その勾配（dWo = Ocatᵀ dAttn と dWv の元になる dO = dAttn Woᵀ）も 0 なので、Wv と Wo は永遠に 0 のままです。L は 1.3093 → 0.4621（1000 ステップ）と文脈なしの最善に収束し、C と Δ は最後まで厳密に 0。**積の両方の因子が 0 だと、勾配も 0 になって抜け出せない**、本物の罠です。
</details>
