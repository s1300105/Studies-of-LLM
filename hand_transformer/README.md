# 手計算で Transformer を「学習1ステップ」回す — 設計書

**ゴール**：小さな GPT（Transformer デコーダ1層）で
**予測 → 損失 → 逆伝播 → 重み更新 → もう一度予測**
を関数電卓と紙で一周し、**損失が下がる瞬間**（と、予測が正解にひっくり返る瞬間）を自分の手で見る。

手でやる価値があるのは「どの数が、どこに、どう流れるか」。
そのために、この設計では **手計算の手間を減らす工夫** と **計算ミスを自分で検出できる仕掛け** を入れています。

> **はじめ方（5分）**
> 1. 用意するもの：関数電卓（exp・ln・√・メモリ M+ があるもの）、A3 用紙1枚と計算用紙。[`workbook/params.md`](workbook/params.md)（全パラメータ）と [`workbook/blank.md`](workbook/blank.md)（記入用シート）を印刷する
> 2. この README は §2（仕様）・§3（記号）・§6（時間計画）・§7（進め方のルール）を読む。§8 は各ステップの「予想しよう」の答えを含むので後で
> 3. [`workbook/step1_setup.md`](workbook/step1_setup.md) を開いて始める。答え合わせは [`workbook/answers.md`](workbook/answers.md)、または `hand_transformer/` で `python3 mini_gpt.py --only 2.1`（NumPy が必要）

## 1. 全体像

```
 入力  <s>   猫    が                        正解  猫   が   鳴く
        │    │    │
 2.1   X0 = E[ids] + P          (3×4)  ─────────────┐ 残差ストリーム
 2.3   U1 = LN(X0)              (3×4)  ← ±1 になるよう設計(1回目)  │
 3.1   Q,K,V = U1·Wq, U1·Wk, U1·Wv     (各 3×4)                    │
 3.2   S_h = Q_h K_hᵀ/√2 + マスク     (ヘッド2本 × 3×3)            │
 3.3   A_h = softmax(S_h)                                          │
 3.4   O_h = A_h V_h → Ocat = [O0|O1] (3×4)                        │
 3.5   Attn = Ocat·Wo           (3×4)                              │
 4.1   X1 = X0 + Attn  ◄───────────────────────────────────────────┘
 4.2   U2 = LN(X1)                                                 │
 4.3   Z = U2·W1 (3×8),  R = ReLU(Z)                               │
 4.4   F = R·W2                 (3×4)                              │
 4.5   X2 = X1 + F     ◄───────────────────────────────────────────┘
 5.1   logits = X2·Wout         (3×5)
 5.2   p = softmax(logits)
 5.3   L = 平均_t ( −log p[t, 正解_t] )
 6.x   逆伝播：上の流れを下から上へ
 7.x   θ ← θ − lr·dθ（180個すべて）→ もう一度 2.1〜5.3 → L' < L ?
```

番号（2.1, 3.2, 6.5 …）は **チェックポイント番号**。ワークブック・解答集・`mini_gpt.py` の表示がすべてこの番号でそろっています。

## 2. モデル仕様と設計判断

元の案（語彙5・系列長3・d_model 4・2ヘッド・FFN 8・1層・マスク付き・バイアスなし）はそのまま採用し、
手計算のために次の点を決めました。

| 項目 | 決定 | 理由 |
|---|---|---|
| 語彙 | `<s>`=0, `猫`=1, `が`=2, `鳴く`=3, `。`=4 | 元案どおり |
| 入力 → 正解 | `<s> 猫 が` → `猫 が 鳴く` | 3位置すべてで次トークン予測（GPTの学習そのもの） |
| d_model / ヘッド / d_k | 4 / 2 / 2 | 元案どおり。ヘッド0 = 列0,1、ヘッド1 = 列2,3 |
| FFN | 4 → 8 → 4、**ReLU** | GPT は GELU だが、ReLU は微分が 0/1 で手計算向き |
| LayerNorm の位置 | **Pre-LN**（GPT-2 型：サブ層の前で正規化） | 残差ストリーム X0 → X1 → X2 が LN を通らない一本道になり、**勾配が残差を素通りする様子がそのまま見える** |
| 最終 LayerNorm | **なし**（GPT-2 にはある） | ① LN 1回分（順・逆で約1時間）節約 ② logits が残差ストリームの各成分の**和に厳密に分解**できる（直接経路＋ヘッド0＋ヘッド1＋FFN）③ 出力層の勾配 dX2 が埋め込みまで無加工で届く |
| LN の γ, β | γ=1, β=0 に**固定**（学習しない） | パラメータを減らす。「正規化」そのものの微分に集中する |
| LN の ε | **0 ちょうど** | σ1 = 0.5, 2, 1 と U1 = ±1 を厳密に保つため（分散が0にならない値を選んである）。正解実装 `mini_gpt.py` も ε = 0。一般の実装は σ² に 1e-5 程度を足す（全成分が等しい行で 0 で割らないための安全策）。足しても解答との差は最大 1.3×10⁻⁴ で、L は 1.3949 のまま |
| LN の分散 | 母分散（÷4） | PyTorch の LayerNorm と同じ |
| 位置情報 | **学習型の位置埋め込み P**（GPT 型） | sin/cos の値（0.8415…）は以降の全計算を汚す。P を自由に選べるので、**U1 = LN(X0) が全成分 ±1 になるよう設計**できる → Q, K, V の計算（144回の積和）が足し算・引き算だけになる。sin/cos 版は発展課題で計算する |
| 出力層 | Wout（4×5）、埋め込みと**共有しない** | 勾配の流れを単純に保つ（重み共有は発展課題） |
| スケーリングとマスク | 1/√d_k = 1/√2、未来の位置のスコアは −∞ | 元論文どおり。−∞ は softmax 後に 0 になる（S の右上の3マス） |
| 損失 | 3位置の交差エントロピーの**平均** | 実装の標準。d logits = (p − y)/3 |
| 最適化 | 素の SGD：θ ← θ − lr·dθ、**lr = 1**（E, P も含む全180個） | 1ステップで「何が起きたか」が一番読みやすい。lr = 1 なので更新は引き算だけ |
| 初期値 | すべて 0.5 刻み（0, ±0.5, ±1 が中心） | 元案どおり。さらに 0 と ±1 を多めにして掛け算を減らす |

**パラメータ数**：E 20 + P 12 + Wq/Wk/Wv 48 + Wo 16 + W1 32 + W2 32 + Wout 20 = **180**

> **このタスクの正直な限界**：`<s>→猫, 猫→が, が→鳴く` は「直前の1語だけ見れば次が決まる」タスクなので、
> 理屈の上では Attention が無くても解けます。手計算で学ぶのは Attention の**仕組み（計算と勾配の流れ）**で、
> Attention が**なぜ必要か**は発展課題「2文タスク」（`extras/two_sentences.py`）で確かめます。

## 3. 記号と形状

行ベクトル規約（各位置のベクトルは行。`X @ W` の形で掛ける）。
添字はすべて0始まりで、位置（行）は t0, t1, t2、次元（列）は d0〜d3、キーは k0〜k2、FFN ユニットは h0〜h7 と書きます（「1列目」のような序数は使いません）。

| 記号 | 形 | 意味 |
|---|---|---|
| E | 5×4 | トークン埋め込み（行 = トークン） |
| P | 3×4 | 位置埋め込み（行 = 位置） |
| X0, X1, X2 | 3×4 | 残差ストリーム（各位置の状態） |
| U1, U2 | 3×4 | LayerNorm の出力 |
| Wq, Wk, Wv, Wo | 4×4 | Attention の射影。Wo の行0,1 はヘッド0 の出力、行2,3 はヘッド1 の出力に掛かる |
| Q, K, V | 3×4 | 列0,1 がヘッド0、列2,3 がヘッド1 |
| S_h, A_h | 3×3 | ヘッド h のスコアと重み（行 = クエリ位置、列 = キー位置、右上はマスク） |
| O_h | 3×2 | ヘッド h の出力。Ocat = [O0 | O1] は 3×4 |
| W1 / W2 | 4×8 / 8×4 | FFN |
| Z, R | 3×8 | FFN 中間層（ReLU 前 / 後） |
| Wout | 4×5 | 出力層（列 = トークン） |
| logits, p | 3×5 | 出力（行 = 位置、列 = 語彙） |
| dX | X と同じ | ∂L/∂X |

## 4. 初期値の設計

全180個の値は [`workbook/params.md`](workbook/params.md)（正本は [`params.json`](params.json)）。
すべて {0, ±0.5, ±1} のどれか（0 が67個、±1 が71個、±0.5 が42個）です。

### 4.1 手計算を楽にする仕掛け

- **U1 が全成分 ±1**：X0 の各行が「2種類の値が2個ずつ」になるよう E と P を選んであるので、
  LN1 の出力は ±1 だけになります（σ = 0.5, 2, 1）。その結果 **Q, K, V = U1·W は重みの行の足し引きだけ**で求まり、すべて 0.5 刻みの値になります。
  3行は互いに直交しています。
- **0 が多い**：Wout は 70%、Wk は 56% が 0。0 との掛け算は飛ばせます。
- **構造的に計算不要な部分がある**：t0 の Attention は自分自身しか見られないので A の t0 行は必ず [1, 0, 0]。
  したがって **Q の t0 行は計算不要**です。また FFN ユニット h3 は、4.3 で Z の h3 列が3位置とも負と分かる「死んだユニット」です。
  分かったあとは、4.4 の W2 の h3 行と、逆伝播の dW1 の h3 列・dW2 の h3 行が計算不要です（Z の h3 列そのものは計算します）。

この工夫が効くのは1回目の順伝播と、U1 を使い回す逆伝播（6.7 は足し引きだけ）です。更新後は E, P がずれて U1' は ±1 でなくなり、重みも4桁の小数になるので、
**2回目の順伝播は1回目よりずっと重い**（§5, §6）。

### 4.2 どうやって選んだか

ランダムに選ぶと、Attention が飽和したり、ReLU が全部死んだり、更新後に損失が上がったりします。
そこで次の条件をすべて満たす値をプログラムで探索して選びました（死んだ ReLU ユニットを1つ、わざと入れてあります）。
探索では「手計算の軽さ」「解釈しやすさ」「学習の見やすさ」の3方針で候補を作って比べ、1ステップの変化がもっともはっきり見え、丸め誤差にも強い案を採りました。

| 条件 | この重みでの値 |
|---|---|
| 値はすべて 0.5 刻み、絶対値 ≤ 1 | ✓ |
| U1 = LN(X0) が厳密に ±1、3行が直交 | ✓ |
| ReLU 入力が 0 に近すぎない（ReLU′(0) の曖昧さを避ける） | min \|Z\| = 0.2821（更新後 0.3216） |
| 両ヘッドの Attention が飽和（one-hot）も一様もしない、ヘッド同士が違う | t1, t2 行の最大重み：ヘッド0 0.7428、ヘッド1 0.5875（ヘッド0 の t2→k2 だけは 0.0004 とほぼ0） |
| ReLU の発火率が 35〜70% | 10/24 = 42% |
| 初期損失が ln 5 ≈ 1.609 付近で、初期予測はほぼ全部ハズレ | L = 1.3949、正解 0/3 |
| 1ステップで損失が10%以上下がり、1次近似が使える精度 | −92%、実際/予測 = 0.877 |
| すべてのパラメータ群に意味のある勾配が届く | 最小は Wq（‖g‖² の 1.0%） |
| 中間値が大きくなりすぎない、更新後も LN の σ が小さすぎない | 1回目の活性値（X, U, Q/K/V, Z, F, logits）は \|値\| ≤ 3.17（スコア S は最大 3.7123、σ² は最大 4）、2回目の σ ≥ 0.478 |
| 逆伝播が数値微分と一致 | 誤差 ≤ 3×10⁻¹⁰ |

> **注意（現実との違い）**：実際の学習では重みの初期値は標準偏差 0.02 程度、学習率は 10⁻³〜10⁻⁴ 程度で、
> 1ステップで損失が 92% も下がることはありません。ここでは「1回で変化が目に見える」ように、大きな重み・1文だけ・lr = 1 を選んでいます。
> 学習率を変えると何が起きるか（lr = 0.25 なら 1.3949 → 1.0055 で正解 2/3、lr = 2 なら 0.0030）は発展課題で確かめます。

## 5. 計算量

数え方の詳細と全チェックポイントの内訳は [`workbook/cost.md`](workbook/cost.md)（`python3 tools/opcount.py` で再集計できます）。

**元の案の見立て「順伝播 約500回、逆伝播 その約2倍」は正しい**：工夫なしに数えると積は 540 回 / 1,116 回（2.07倍）。
ただし手でやる量は、この重みの工夫と「計算しなくてよい部分」の見極めで大きく変わります。

| 区間 | 工夫なしの積 | 計算不要（0との積・構造的に不要） | 実際に掛ける回数 | うち小数×小数 | 純粋な計算時間（推定） |
|---|---:|---:|---:|---:|---:|
| 1回目の順伝播（2.1–5.3） | 540 | 258 | 282 | 8 | 1.33h |
| 逆伝播（6.1–6.9） | 1,116 | 491 | 625 | 232 | 2.77h |
| 更新と1次予測（7.1–7.2） | 181 | 32 | 149 | 148 | 0.88h |
| 2回目の順伝播（7.3–7.4） | 540 | 112 | 428 | 400 | 2.97h |
| **合計**（準備の行和・列和 0.12h を含む） | 2,377 | 893（38%） | **1,484** | 788 | **8.06h** |

- **一番重いのは 7.3（2回目の順伝播、175分＝全計算時間の36%）**。積の数は1回目と同じなのに、小数×小数が 8 回 → 400 回に増える。
  同じ Q, K, V の計算が、1回目は5分、2回目は33分。
- 20時間の内訳：計算 8.1h ＋ 検算 1.5h ＋ 照合 0.6h ＋ 導出 2.5h ＋ 予備 1.5h ＋ **理解・予想・誤り探し 5.8h**。
  計算そのものは半分以下で、残りの時間を「なぜそうなるか」に使う設計です。
- 時間モデル（小数×小数 16秒、±1との積 4秒、exp・√ 15秒、1つ書く 8秒 など）は `cost.md` §2。小数×小数を 12秒 / 20秒にすると合計は 7.4h / 8.7h。

## 6. 時間計画（20時間）

元の案の7ステップをそのまま使い、配分を見直しました。

| ステップ | 元の案 | 見直し後 | 内容 | チェックポイント |
|---|---:|---:|---|---|
| 1 準備・地図作り | 1h | **1.0h** | 計算グラフと形状表を描く。分岐点（U1, X1, X0）を確認。精度ルールを決め、全重み行列の行和・列和（検算用）を先に求める | — |
| 2 埋め込み＋LN1 | 1h | **0.5h** | X0、LN1。U1 が ±1 になることを確認 | 2.1–2.3 |
| 3 Attention | 4h | **1.75h** | Q（t1, t2 行だけ）・K・V、スコア、softmax、AV、Wo | 3.1–3.5 |
| 4 残差・LN2・FFN | 3h | **1.75h** | ここで初めて本物の √ が出る | 4.1–4.5 |
| 5 出力・損失 | 1h | **0.75h** | logits、softmax、損失 | 5.1–5.3 |
| 6 逆伝播 | 7h | **8.0h** | **導出 2.5h**（数字を使わずに [`derivations.md`](workbook/derivations.md)）＋ 数値 5.5h | 6.1–6.9 |
| 7 更新 → 再順伝播 | 3h | **4.75h** | 1次予測と更新 1.0h ＋ 2回目の順伝播 3.75h | 7.1–7.4 |
| 予備・振り返り | — | **1.5h** | ミス探し、振り返り、余れば手で数値微分 | — |

主な変更点：

- **1回目の順伝播は 9h → 4.75h**：U1 = ±1 と 0 の多さのおかげで、掛け算の大半が「符号付きコピー」か「スキップ」になる（計算・検算・照合を合わせて約1.7h、うち純粋な計算は1.33h。残りは式の意味を確かめ、予想する時間）。
- **逆伝播に導出の時間を別枠で確保**：softmax・LayerNorm の微分を数字の前に導いておけば、数値計算は代入するだけになる。
- **ステップ7は 3h → 4.75h**：更新後は小数×小数の掛け算がほとんど（0との積を除いた428回中400回）になる、隠れた山場。検算込みで約4.7hかかるので、1回目の順伝播で浮いた時間から回した。ステップ6が終わった時点で遅れていたら [`step7_update.md`](workbook/step7_update.md) の省略案を使う。
- **予備 1.5h**：約1,500回の掛け算（＋exp・√・割り算など約250回）でミスが一度も起きない確率は実質ゼロ。ミスを見つけて直す時間を最初から計画に入れる。

## 7. 進め方のルール

1. **有効数字4桁で記録**。1つの内積の途中では丸めない（電卓の M+ で累積）。
2. **QKᵀ は厳密に計算してから最後に 1/√2（= 0.70711）を1回掛ける**。softmax は行の最大値を引いてから。損失は −log p ではなく logsumexp − logit で。
3. **答えを見る前に検算する**：
   - 行列積は行和チェックサム：$\text{rowsum}(XW) = X\cdot(W\mathbf 1)$。1回目は W の行和が 0.5 刻みなので暗算できる。
   - 不変量：LN 出力の各行は平均0・二乗平均1、softmax の行和1、dlogits と dS の行和0、LN 逆伝播の出力は各行の和0かつ LN 出力と直交、など（一覧は [`derivations.md` の末尾](workbook/derivations.md#検算チェックリスト計算中いつでも使える)）。
4. **チェックポイントごとに解答と照合**（[`answers.md`](workbook/answers.md) または `python3 mini_gpt.py --only 3.2`）。
   許容差は |自分 − 解答| ≤ 0.002 + 0.002·|解答|。
5. **ずれていたら10分だけ探し、見つからなければ解答の値で上書きして先へ進む**（誤差の伝播を防ぐ）。ミスは種類（転置、符号、分岐での足し忘れ、÷3 や 1/√2 の忘れ）ごとに記録する。
6. **計算する前に予想する**：t2 のクエリはどのキーを見るか、勾配の符号はどうなるか、どの logit が上がるか。予想と結果のずれが一番の学びになります。

## 9. 追加でやった方がいいこと

本編を終えたら取り組む課題を、優先度順に [`extras/README.md`](extras/README.md) にまとめました。どれも実行して結果を確かめてあります。

| 優先度 | 課題 | 何が分かるか | コマンド |
|---|---|---|---|
| **must** | M1 2文タスク（猫が鳴く / 犬が吠える） | 本編は直前の1語で解けるが、こちらは t2 の入力がどちらも「が」なので**前を振り返らないと解けない**。Attention ありは損失の下限 0.231 に届き、なしは 0.462 で鳴く/吠える 50:50 に張り付く。ヘッド0 が「犬検出器」になる | `python3 extras/two_sentences.py` |
| **must** | M2 Wout の1成分を手で数値微分 | 勾配 =「少し動かしたら損失がどれだけ変わるか」を逆伝播と独立に確かめる。Wout だけなら logits の1列しか変わらないので30分で済む（本編 7.4 の5を予備時間にやった人は、h を変える表の確認だけでよい） | `python3 extras/numgrad_by_hand.py` |
| **must** | M3 多ステップ学習と学習率スキャン | 1次近似が成り立つ範囲と壊れる範囲（実際/予測：lr 0.25 で 1.06、lr 2 で 0.47）。このモデルは lr = 8 までは揺れながらも収束し、lr = 9 で発散する | `python3 extras/lr_scan.py` |
| **must** | M4 見ずに自分で実装して answers.md と一致させる | 手で追った流れをコードとして固める。よくあるバグ11種が「どのチェックポイントで最初にずれるか」の表つき | `python3 extras/bug_signatures.py` |
| should | S1 因果マスクを外す | 学習損失は下がる（カンニング）のに、`<s>` からの生成が壊れる | `python3 extras/no_mask.py` |
| should | S2 自己回帰生成と KV キャッシュ | 学習（全位置を並列）と推論（1語ずつ）の違い。キャッシュしても logits が一致すること | `python3 extras/kv_cache.py` |
| should | S3 ロジット分解（更新前後） | 最終LNが無いので logits =（直接経路＋ヘッド0＋ヘッド1＋FFN）·Wout と厳密に分かれる。更新で誰が正解を押し上げたか | `python3 extras/decompose_update.py` |
| should | S4 なぜ √d_k で割るのか | d_k = 2 の手計算では見えない。d_k = 1024 で割らないと最大の重みが 0.959（ほぼ one-hot）になり、勾配が消える | `python3 extras/scaling.py` |
| should | S5 LayerNorm の γ, β の勾配 | 固定した γ, β が本来どう学習されるか。手で求めた dU1, dU2 からほぼ追加コストなしで出せる | `python3 extras/ln_affine.py` |
| should | S6 PyTorch に移植して autograd と照合、AdamW | 手で計算した逆伝播がフレームワークの中で何をしているか。Adam の1ステップ目は勾配の大きさによらずほぼ ±lr | `python3 extras/torch_port.py` |
| could | C1–C6 | Pre-LN と Post-LN、sin/cos 位置埋め込みと RoPE、重み共有、2層の induction head、nanoGPT、ヘッドの対称性 | `extras/README.md` 参照 |

**このワークブックでは学べないこと**（汎化、Adam や warmup、実際の初期値の小ささ、トークナイズ、長い文脈のコストなど）と、その補い方も `extras/README.md` の最後にまとめています。

おすすめの順番：**M1 → M2 → M3 → S1 → S2 → S3 → M4**。

## 10. ファイル構成と使い方

```
hand_transformer/
├── README.md              ← この設計書
├── params.json            ← 初期パラメータと学習率（正本）
├── mini_gpt.py            ← NumPy の正解実装（手計算と同じ順序・記号）
├── workbook/
│   ├── step1_setup.md … step7_update.md   ← ステップごとの手順書（記入欄つき）
│   ├── derivations.md     ← 逆伝播の導出ノートと検算チェックリスト
│   ├── params.md          ← 全パラメータの表（印刷用）
│   ├── blank.md           ← 全チェックポイントの記入用シート（印刷用）
│   ├── answers.md         ← 解答集
│   └── cost.md            ← 演算回数と所要時間の見積もり
├── tools/                 ← opcount.py（演算回数の集計）、sync_worksheets.py（記入欄の同期）
└── extras/                ← 発展課題（README.md とスクリプト）
```

```bash
python3 mini_gpt.py --only 3.3      # チェックポイント 3.3 の正解だけ見る
python3 mini_gpt.py --step 6        # ステップ6（逆伝播）の正解をまとめて見る
python3 mini_gpt.py --gradcheck     # 逆伝播が数値微分と一致するか確認
python3 mini_gpt.py --decompose     # logits を「直接経路／ヘッド0／ヘッド1／FFN」の寄与に分解
python3 mini_gpt.py --train 20      # 同じ文で20ステップ学習させる
```

`answers.md`・`blank.md`・`params.md` は `params.json` から自動生成しています。
重みを変えたら `python3 mini_gpt.py --markdown > workbook/answers.md`、`--blank > workbook/blank.md`、`--params-md > workbook/params.md` で作り直し、`python3 tools/sync_worksheets.py` で手順書の記入欄を同期してください。
