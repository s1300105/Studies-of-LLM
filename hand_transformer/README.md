# 手計算で Transformer を「学習1ステップ」回す — 設計書

**ゴール**：小さな GPT（Transformer デコーダ1層）で
**予測 → 損失 → 逆伝播 → 重み更新 → もう一度予測**
を関数電卓と紙で一周し、**損失が下がる瞬間**（と、予測が正解にひっくり返る瞬間）を自分の手で見る。

手でやる価値があるのは「どの数が、どこに、どう流れるか」。
そのために、この設計では **手計算の手間を減らす工夫** と **計算ミスを自分で検出できる仕掛け** を入れています。

> **このワークブックで起きること（学習率 1 の SGD を1回）**
>
> | | 更新前 | 更新後 |
> |---|---|---|
> | 損失 L | 1.3949 | **0.1056** |
> | 予測（各位置の argmax） | `<s>` `<s>` `。`（全部ハズレ） | **`猫` `が` `鳴く`（全部正解）** |
> | 正解トークンの確率 | 0.2313 / 0.2674 / 0.2462 | 0.8608 / 0.9340 / 0.9062 |
>
> 更新前に勾配から予言できる下がり幅 −lr‖g‖² = **−1.4701**、実際の下がり幅 **−1.2893**（比 0.877）。

## 1. 全体像

```
 入力  <s>   猫    が                        正解  猫   が   鳴く
        │    │    │
 2.1   X0 = E[ids] + P          (3×4)  ─────────────┐ 残差ストリーム
 2.3   U1 = LN(X0)              (3×4)  ← ±1 だけになるよう設計     │
 3.1   Q,K,V = U1·Wq, U1·Wk, U1·Wv     (各 3×4)                    │
 3.2   S_h = Q_h K_hᵀ/√2 + マスク     (ヘッド2本 × 3×3)            │
 3.3   A_h = softmax(S_h)                                          │
 3.4   O_h = A_h V_h → Ocat = [O0|O1] (3×4)                        │
 3.5   Attn = Ocat·Wo           (3×4)                              │
 4.1   X1 = X0 + Attn  ◄───────────────────────────────────────────┘
 4.2   U2 = LN(X1)                                                 │
 4.3   Z = U2·W1 (3×8),  R = ReLU(Z)                               │
 4.4   F = R·W2                 (3×4)                              │
 4.5   X2 = X1 + F     ◄───────────────────────────────────────────┘
 5.1   logits = X2·Wout         (3×5)
 5.2   p = softmax(logits)
 5.3   L = 平均_t ( −log p[t, 正解_t] )
 6.x   逆伝播：上の流れを下から上へ
 7.x   θ ← θ − lr·dθ（180個すべて）→ もう一度 2.1〜5.3 → L' < L ?
```

番号（2.1, 3.2, 6.5 …）は **チェックポイント番号**。ワークブック・解答集・`mini_gpt.py` の表示がすべてこの番号でそろっています。

## 2. モデル仕様と設計判断

元の案（語彙5・系列長3・d_model 4・2ヘッド・FFN 8・1層・マスク付き・バイアスなし）はそのまま採用し、
手計算のために次の点を決めました。

| 項目 | 決定 | 理由 |
|---|---|---|
| 語彙 | `<s>`=0, `猫`=1, `が`=2, `鳴く`=3, `。`=4 | 元案どおり |
| 入力 → 正解 | `<s> 猫 が` → `猫 が 鳴く` | 3位置すべてで次トークン予測（GPTの学習そのもの） |
| d_model / ヘッド / d_k | 4 / 2 / 2 | 元案どおり。ヘッド0 = 列0,1、ヘッド1 = 列2,3 |
| FFN | 4 → 8 → 4、**ReLU** | GPT は GELU だが、ReLU は微分が 0/1 で手計算向き |
| LayerNorm の位置 | **Pre-LN**（GPT-2 型：サブ層の前で正規化） | 残差ストリーム X0 → X1 → X2 が LN を通らない一本道になり、**勾配が残差を素通りする様子がそのまま見える** |
| 最終 LayerNorm | **なし**（GPT-2 にはある） | ① LN 1回分（順・逆で約1時間）節約 ② logits が残差ストリームの各成分の**和に厳密に分解**できる（直接経路＋ヘッド0＋ヘッド1＋FFN）③ 出力層の勾配 dX2 が埋め込みまで無加工で届く |
| LN の γ, β | γ=1, β=0 に**固定**（学習しない） | パラメータを減らす。「正規化」そのものの微分に集中する |
| LN の ε | 0 | 手計算をきれいに保つ（分散が0にならない値を選んである）。実装では 1e-5 程度を足す |
| LN の分散 | 母分散（÷4） | PyTorch の LayerNorm と同じ |
| 位置情報 | **学習型の位置埋め込み P**（GPT 型） | sin/cos の値（0.8415…）は以降の全計算を汚す。P を自由に選べるので、**U1 = LN(X0) が全成分 ±1 になるよう設計**できる → Q, K, V の計算（144回の積和）が足し算・引き算だけになる。sin/cos 版は発展課題で計算する |
| 出力層 | Wout（4×5）、埋め込みと**共有しない** | 勾配の流れを単純に保つ（重み共有は発展課題） |
| スケーリング | 1/√d_k = 1/√2 | 元論文どおり |
| 損失 | 3位置の交差エントロピーの**平均** | 実装の標準。d logits = (p − y)/3 |
| 最適化 | 素の SGD：θ ← θ − lr·dθ（E, P も含む全180個） | 1ステップで「何が起きたか」が一番読みやすい |
| 初期値 | すべて 0.5 刻み（0, ±0.5, ±1 が中心） | 元案どおり。さらに 0 と ±1 を多めにして掛け算を減らす |

**パラメータ数**：E 20 + P 12 + Wq/Wk/Wv 48 + Wo 16 + W1 32 + W2 32 + Wout 20 = **180**

> **このタスクの正直な限界**：`<s>→猫, 猫→が, が→鳴く` は「直前の1語だけ見れば次が決まる」タスクなので、
> 理屈の上では Attention が無くても解けます。手計算で学ぶのは Attention の**仕組み（計算と勾配の流れ）**で、
> Attention が**なぜ必要か**は発展課題「2文タスク」（`extras/two_sentences.py`）で確かめます。

## 3. 記号と形状

行ベクトル規約（各位置のベクトルは行。`X @ W` の形で掛ける）。

| 記号 | 形 | 意味 |
|---|---|---|
| E | 5×4 | トークン埋め込み（行 = トークン） |
| P | 3×4 | 位置埋め込み（行 = 位置） |
| X0, X1, X2 | 3×4 | 残差ストリーム（各位置の状態） |
| U1, U2 | 3×4 | LayerNorm の出力 |
| Wq, Wk, Wv, Wo | 4×4 | Attention の射影 |
| Q, K, V | 3×4 | 列0,1 がヘッド0、列2,3 がヘッド1 |
| S_h, A_h | 3×3 | ヘッド h のスコアと重み（行 = クエリ位置、列 = キー位置、右上はマスク） |
| O_h | 3×2 | ヘッド h の出力。Ocat = [O0 | O1] は 3×4 |
| W1 / W2 | 4×8 / 8×4 | FFN |
| Z, R | 3×8 | FFN 中間層（ReLU 前 / 後） |
| Wout | 4×5 | 出力層（列 = トークン） |
| logits, p | 3×5 | 出力（行 = 位置、列 = 語彙） |
| dX | X と同じ | ∂L/∂X |

## 4. 初期値の設計

全180個の値は [`workbook/params.md`](workbook/params.md)（正本は [`params.json`](params.json)）。
すべて {0, ±0.5, ±1} のどれか（0 が67個、±1 が71個、±0.5 が42個）です。

### 4.1 手計算を楽にする仕掛け

- **U1 が全成分 ±1**：X0 の各行が「2種類の値が2個ずつ」になるよう E と P を選んであるので、
  LN1 の出力は ±1 だけになります（σ = 0.5, 2, 1）。その結果 **Q, K, V = U1·W は重みの行の足し引きだけ**で求まり、すべて 0.5 刻みの値になります。
  3行は互いに直交しています。
- **0 が多い**：Wout は 70%、Wk は 56% が 0。0 との掛け算は飛ばせます。
- **構造的に計算不要な部分がある**：位置0の Attention は自分自身しか見られないので A の0行目は必ず [1, 0, 0]。
  したがって **Q の0行目は計算不要**です。死んだ FFN ユニット h3 の列・行も計算不要です。

この工夫が効くのは1回目の順伝播だけです。更新後は E, P がずれて U1' は ±1 でなくなり、重みも4桁の小数になるので、
**2回目の順伝播は1回目よりずっと重い**（§5, §6）。

### 4.2 どうやって選んだか

ランダムに選ぶと、Attention が飽和したり、ReLU が全部死んだり、更新後に損失が上がったりします。
そこで次の条件をすべて満たす値を、方針の違う3案（手計算の軽さ優先／解釈しやすさ優先／学習の見やすさ優先）から探索し、
審査で「学習の見やすさ優先」案を採用したうえで他案の良い点を移植しました（例：死んだ ReLU ユニットを1つ入れる）。

| 条件 | この重みでの値 |
|---|---|
| 値はすべて 0.5 刻み、絶対値 ≤ 1 | ✓ |
| U1 = LN(X0) が厳密に ±1、3行が直交 | ✓ |
| ReLU 入力が 0 に近すぎない（ReLU′(0) の曖昧さを避ける） | min \|Z\| = 0.2821（更新後 0.3216） |
| 両ヘッドの Attention が飽和も一様もしない、ヘッド同士が違う | 位置1,2 の最大重み 0.7428 / 0.5875 |
| ReLU の発火率が 35〜70% | 10/24 = 42% |
| 初期損失が ln 5 ≈ 1.609 付近で、初期予測はほぼ全部ハズレ | L = 1.3949、正解 0/3 |
| 1ステップで損失が10%以上下がり、1次近似が使える精度 | −92%、実際/予測 = 0.877 |
| すべてのパラメータ群に意味のある勾配が届く | 最小は Wq（‖g‖² の 1.0%） |
| 中間値が大きくなりすぎない、更新後も LN の σ が小さすぎない | 1回目の \|中間値\| ≤ 3.17、2回目の σ ≥ 0.478 |
| 逆伝播が数値微分と一致 | 誤差 ≤ 3×10⁻¹⁰ |

> **注意（現実との違い）**：実際の学習では重みの初期値は標準偏差 0.02 程度、学習率は 10⁻³〜10⁻⁴ 程度で、
> 1ステップで損失が 92% も下がることはありません。ここでは「1回で変化が目に見える」ように、大きな重み・1文だけ・lr = 1 を選んでいます。
> 学習率を変えると何が起きるか（lr = 0.25 なら 1.3949 → 1.0055 で正解 2/3、lr = 2 なら 0.0030）は発展課題で確かめます。

## 6. 時間計画（20時間）

元の案の7ステップをそのまま使い、配分を見直しました。

| ステップ | 元の案 | 見直し後 | 内容 | チェックポイント |
|---|---:|---:|---|---|
| 1 準備・地図作り | 1h | **1.0h** | 計算グラフと形状表を描く。分岐点（U1, X1, X0）を確認。精度ルールを決め、全重み行列の行和・列和（検算用）を先に求める | — |
| 2 埋め込み＋LN1 | 1h | **0.5h** | X0、LN1。U1 が ±1 になることを確認 | 2.1–2.3 |
| 3 Attention | 4h | **2.5h** | Q（1,2行目だけ）・K・V、スコア、softmax、AV、Wo | 3.1–3.5 |
| 4 残差・LN2・FFN | 3h | **1.75h** | ここで初めて本物の √ が出る | 4.1–4.5 |
| 5 出力・損失 | 1h | **0.75h** | logits、softmax、損失 | 5.1–5.3 |
| 6 逆伝播 | 7h | **8.0h** | **導出 2.5h**（数字を使わずに [`derivations.md`](workbook/derivations.md)）＋ 数値 5.5h | 6.1–6.9 |
| 7 更新 → 再順伝播 | 3h | **4.0h** | 1次予測と更新 0.75h ＋ 2回目の順伝播 3.25h | 7.1–7.4 |
| 予備・振り返り | — | **1.5h** | ミス探し、振り返り、余れば手で数値微分 | — |

主な変更点：

- **1回目の順伝播は 9h → 5.5h**：U1 = ±1 と 0 の多さのおかげで、掛け算の大半が「符号付きコピー」か「スキップ」になる。
- **逆伝播に導出の時間を別枠で確保**：softmax・LayerNorm の微分を数字の前に導いておけば、数値計算は代入するだけになる。
- **再順伝播は 3h → 3.25h**：更新後は小数×小数の掛け算がほとんどになる、隠れた山場。遅れた場合の省略案は [`step7_update.md`](workbook/step7_update.md)。
- **予備 1.5h**：約1,700回の非自明な演算でミスが一度も起きない確率は実質ゼロ。ミスを見つけて直す時間を最初から計画に入れる。

## 7. 進め方のルール

1. **有効数字4桁で記録**。1つの内積の途中では丸めない（電卓の M+ で累積）。
2. **QKᵀ は厳密に計算してから最後に 1/√2（= 0.70711）を1回掛ける**。softmax は行の最大値を引いてから。損失は −log p ではなく logsumexp − logit で。
3. **答えを見る前に検算する**：
   - 行列積は行和チェックサム：$\text{rowsum}(XW) = X\cdot(W\mathbf 1)$。W の行和は 0.5 刻みなので暗算できる。
   - 不変量：LN 出力の各行は平均0・二乗平均1、softmax の行和1、dlogits と dS の行和0、LN 逆伝播の出力は各行の和0かつ LN 出力と直交、など（一覧は [`derivations.md` の末尾](workbook/derivations.md#検算チェックリスト計算中いつでも使える)）。
4. **チェックポイントごとに解答と照合**（[`answers.md`](workbook/answers.md) または `python mini_gpt.py --only 3.2`）。
   許容差は |自分 − 解答| ≤ 0.002 + 0.002·|解答|。
5. **ずれていたら10分だけ探し、見つからなければ解答の値で上書きして先へ進む**（誤差の伝播を防ぐ）。ミスは種類（転置、符号、分岐での足し忘れ、÷3 や 1/√2 の忘れ）ごとに記録する。
6. **計算する前に予想する**：位置2のクエリはどのキーを見るか、勾配の符号はどうなるか、どの logit が上がるか。予想と結果のずれが一番の学びになります。

## 10. ファイル構成と使い方

```
hand_transformer/
├── README.md              ← この設計書
├── params.json            ← 初期パラメータと学習率（正本）
├── mini_gpt.py            ← NumPy の正解実装（手計算と同じ順序・記号）
├── workbook/
│   ├── step1_setup.md … step7_update.md   ← ステップごとの手順書（記入欄つき）
│   ├── derivations.md     ← 逆伝播の導出ノートと検算チェックリスト
│   ├── params.md          ← 全パラメータの表（印刷用）
│   ├── blank.md           ← 全チェックポイントの記入用シート（印刷用）
│   ├── answers.md         ← 解答集
│   └── cost.md            ← 演算回数と所要時間の見積もり
└── extras/                ← 発展課題（README.md とスクリプト）
```

```bash
python mini_gpt.py --only 3.3      # チェックポイント 3.3 の正解だけ見る
python mini_gpt.py --step 6        # ステップ6（逆伝播）の正解をまとめて見る
python mini_gpt.py --gradcheck     # 逆伝播が数値微分と一致するか確認
python mini_gpt.py --decompose     # logits を「直接経路／ヘッド0／ヘッド1／FFN」の寄与に分解
python mini_gpt.py --train 20      # 同じ文で20ステップ学習させる
```

`answers.md`・`blank.md`・`params.md` は `params.json` から自動生成しています。
重みを変えたら `python mini_gpt.py --markdown > workbook/answers.md` などで作り直してください。
